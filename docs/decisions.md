- **맥락**: DAU 2천 서비스가 월 $86 청구된 실사례 분석 (Threads @kindainvestor). 원인은 트래픽이 아니라 **ISR 남용**: `revalidate: 60` × 동적 URL 9,649개 → 재생성마다 Function Duration + ISR Writes 이중 과금. 부가 요인: next.config `headers()`의 Cache-Control이 페이지 `revalidate`를 덮어써 s-maxage=60 고정(두 번 배포하고 발견), 크롤러 트래픽, Observability 과금.
- **우리 방어선 (Phase 5~6에서 지킬 것)**:
  1. **페이지 캐시는 on-demand 우선**: 쓰기(제보·다녀왔다면·리뷰)가 우리 앱을 거치므로 `revalidateTag`/`revalidatePath`로 변경 시에만 재생성. 주기 revalidate는 보조로 3600s 이상. **`revalidate: 60` 같은 분 단위 금지** — 우리 데이터는 분 단위 신선도가 필요 없다.
  2. **next.config `headers()`에 페이지 경로 Cache-Control 금지** — 페이지 revalidate를 무력화한다. 폰트·정적 자산(`/fonts/*` 등)만 허용.
  3. URL 규모 자각: /place/[id] 452 + /gu/[name] 25 ≈ 477개 (그 사례의 1/20). on-demand면 재생성은 실제 데이터 변경 횟수에 비례.
  4. Observability Plus 켜지 않는다.
  5. **Hobby 플랜 유지** — 한도 초과 시 과금이 아니라 정지라 요금 폭탄이 구조적으로 불가능. Pro 전환 시 Spend Management 지출 상한을 반드시 같이 설정.
  6. 폰트는 dynamic subset (아래 결정).
- **재검토 조건**: Pro 전환 시, 또는 Phase 5 SSR 페이지 추가 시 이 목록 재확인.

- **빈 상태 ＋ 타일만 176 → 112 폭**(2026-09-03 저녁, 320 실측 후): 타일이 176이면 320에서 오른쪽 안내 열이 49px밖에 안 남아 "첫 사진을 올려주세요"(113px)가 네 줄로 접힌다. **불변식은 "행 높이가 같다"이지 "폭이 같다"가 아니다** — 높이 128은 그대로 두고 폭만 좁혔다(280 − 112 − 12 − 12 − 16 = 128 ≥ 113). 사진이 있는 스트립의 타일과 끝 ＋ 타일은 176 그대로(빈 상태와 나란히 보이는 일이 없다).
- **사진 상한 10장**(`MAX_PLACE_PHOTOS`, lib/data.ts). UI 상수가 아니라 도메인 규칙이라 데이터 계층에 두고 변환에서 `slice`로 막는다. 근거: 한 가게에 필요한 건 음식·간판·내부 정도고, 익명 업로드라 상한이 없으면 도배가 가장 싼 공격이다.
- **데이터 모양 `photoUrls: string[]` → `photos: Photo[]`**(`{ id, url, uploadedAt }`). 업로드 날짜를 보여주려면 배열 원소가 문자열일 수 없다. 이름을 그대로 두면 필드가 거짓말이 되므로 개명했다(참조처 7곳). **`thumbnailUrl = photos[0]?.url ?? null` 파생은 유지** — 카드·마커는 무변경. 목 단계의 `id`는 `{placeId}-p{n}` 파생이고 Phase 6에서 DB uuid로 바뀐다.
- **뷰어는 네이티브 `<dialog>` + `showModal()` + body 포털**. 이유 둘: (1) `.saeu-sheet`가 `transform: translateY()`라 시트 안의 `position: fixed`는 뷰포트가 아니라 시트를 기준으로 잡힌다 — 전체 화면이 안 나온다. (2) top layer는 z 경쟁(시트 z-20, 드롭다운 z-30, 토스트 z-10) 자체를 없애고 포커스 트랩·`inert`·Escape·포커스 복원을 공짜로 준다. 대가는 jsdom에 `showModal`이 없어 `vitest.setup.ts`에 스텁 4줄.
- **좌우 넘김은 CSS scroll-snap, JS 제스처 없음**. 바텀시트가 겪은 pointer-capture 리타겟·non-passive touchmove 함정은 전부 "세로 시트 vs 가로 스트립" 경합에서 나온 것인데, 포털된 단독 표면에는 그 경합이 없다.
- **뒤로가기**: 뷰어를 열 때 `history.pushState({saeuDetail:true, saeuPhoto:true}, "", location.pathname)` — **URL은 바꾸지 않는다**(바꾸면 `use-map-screen`의 `PLACE_PATH` 재동기화가 깨지고, 사진 인덱스는 아직 공유할 자원이 아니다). ⚠︎ **`openDetail` 멱등 가드가 이 설계의 전제다** — pathname이 그대로라 뷰어를 닫을 때 popstate가 같은 id로 `openDetail`을 다시 부르고 `setSnap("half")`가 실행돼 **전체로 펼쳐 둔 시트가 요약으로 튄다**. 같은 id면 no-op으로 막는다.
- **뒤집은 결정 — 신고는 "준비 중이에요" 토스트가 아니다**(2026-09-02 미구현 입구 목록). **사진 신고만** 사유 선택 + 목 저장까지 실제로 동작한다(가게 신고·리뷰 신고는 그대로 토스트). 이유: 신고는 다른 미구현 입구와 성격이 다르다 — 나머지는 "아직 못 만든 편의 기능"이지만, 익명 업로드 이미지에 대한 신고는 **없으면 안 되는 안전장치**다. 사유 4개(부적절한 사진/다른 가게 사진/광고·도배/기타), **행 탭이 곧 제출**이라 확인 버튼이 없다 — 고르고도 안 낸 상태를 만들지 않는다(네이버·인스타 신고 시트의 문법).
- **실패 토스트는 뷰어 안에 따로 렌더한다.** 기존 토스트는 z-10이라 top layer 아래에 무조건 가리고, 신고 실패 시에는 뷰어를 닫으면 안 된다(무엇이 실패했는지 사라진다). 성공만 뷰어를 닫고 기존 토스트를 쓴다. 타이머 호출자가 셋이 되면 `lib/use-notice.ts`로 승격한다.
- **새 토큰 4개**: `bg-immersive`(common-100) · `fg-on-immersive`(common-0) — 딤·몰입 표면 Semantic 자리가 비어 있었다. 여기에 `bg-immersive-raised`(gray-800) · `fg-on-immersive-secondary`(gray-400)를 더했다(아래 항목).
- **뷰어 chrome 재조정**(같은 날, 실제 화면을 보고): 날짜·[신고]가 12 맨 텍스트라 **작고 떠 있었다** — [신고]의 실측 탭 영역이 20×17px로 44px 기준에 한참 못 미쳤다. 날짜는 14 medium + 회색 " 등록"(그냥 날짜만 있으면 무슨 날짜인지 모른다), [신고]는 아이콘 16 + 14 medium의 **44px 알약**, 상단 ✕·카운터도 같은 알약 표면으로 통일. 근거 둘: (1) 탭 영역 44px은 타협 대상이 아니다, (2) 흰 접시 사진이 뒤에 오면 맨 흰 아이콘·글자는 배경과 같은 색이 된다 — 몰입 표면의 컨트롤에는 자기 배경이 필요하다(인스타·네이버 뷰어의 문법). 알약 색은 브랜드 레드가 아닌 gray-800이라 "채운 레드는 화면당 한 곳" 규칙과 무관하다.

## 2026-09-03 — 상세 요약 높이 50% → 30%(최소 270px)

- **결정**: 상세 시트의 기본 스냅을 `max(50dvh, 300px)` → **`max(30dvh, 270px)`**. 요약에서 보이는 것은 사진 스트립 + 상호 블록(상호·카테고리·**"3일 전 확인"**)까지고, 정보 블록·버튼 줄은 본문 스크롤이나 전체 펼침으로 본다.
- **이유**: 사용자 피드백 — "지도를 너무 가리는 느낌". 지도 화면에서 시트가 화면 절반을 먹으면 **정작 지도가 보조가 된다**. 2026-09-02 항목의 재검토 조건("요약 높이 50%는 사용감 피드백 시")이 그대로 발동한 경우다.
- **하한 270px은 임의값이 아니다**: 헤더 44 + 사진 144 + 상호 블록 = 확인 캡션 바닥 **257px**(320·390, 긴 상호 포함 실측 동일 — 상호는 1줄 truncate) + 바닥 여백 13. 30dvh만 쓰면 844에서 253px이라 캡션이 4px 잘리므로 `max()`의 하한이 실제로 이기는 값이다(1000px 이상 뷰포트에서만 30%가 이긴다).
- **뒤집은 결정**: 2026-09-02 "요약 상태 정의 = 50dvh(최소 300px)", 2026-09-03 "요약에서 4번 버튼 줄까지 보이는 것이 수용 기준"(사진 176×128 항목). **사진 타일 크기는 그대로 둔다** — 높이 예산이 더는 버튼 줄에 묶여 있지 않으므로 128을 112로 내릴 이유가 사라졌다. 320×568에서 [길찾기]가 접히던 것도 이제 결함이 아니라 정의된 동작이다.
- **주 액션이 접히는 대가**: [길찾기](채운 레드)가 요약에서 안 보인다. 받아들이는 근거는 (1) 상세를 연 직후의 판단 재료는 사진·상호·신선도이고, 길찾기는 그 판단 **뒤**에 오는 액션이며, (2) 본문이 스크롤 컨테이너라 요약에서도 손가락 한 번이면 닿는다(스크롤 체이닝). 네이버지도·카카오맵도 첫 스냅은 이름·거리·신선도까지다.
- **재검토 조건**: 길찾기 도달률이 문제가 되면 요약 높이가 아니라 **요약 상태의 고정 액션 바**(시트 하단에 겹치는 줄)를 검토한다 — 높이를 되돌리지 않는다.

- **결정**: 화면 2 정보 블록 첫 줄에 `(3)(8) 가락시장역 2-1번출구에서 90m`를 넣는다. 캐치테이블 상세의 문법을 가져오되 **거리는 역 중심이 아니라 가장 가까운 출구까지** 잰다. 역이 멀거나 없으면(`STATION_NEARBY_MAX_M` = 800m) 그 줄을 안 그리고 주소만 남긴다. 도로명 주소는 `fg-secondary`로 한 단계 낮춘다 — "어느 역 근처냐"가 서울에서는 도로명보다 먼저 읽히는 정보다.
- **거리 기준을 출구로 잡은 근거(실측 50곳)**: 역 중심 기준 중앙값 255m → 출구 기준 **218m**. 출구가 **중앙값 53m·평균 61m 짧고**(최대 234m: 삼각지역 439m→205m) 46곳이 짧아졌다. 사람이 걷기 시작하는 지점은 역 중심이 아니라 출구다. 출구 번호는 50/50 확보됐다.
- **정확도(직접 물어서 답한 값)**: ① 역 좌표는 Wikidata(CC0, 독립 소스) 대조 편차 중앙값 21m·평균 31m, 100m 이내 46/47, 최대 145m(옥수). ② 가게 좌표는 독립 지오코딩으로 건물이 특정된 4곳에서 1·4·4·24m(동피랑 1m, 동강해물찜 4m — 상호까지 일치). ③ "어느 역이냐"는 1위↔2위 격차 중앙값 406m(최소 44m)로 좌표 오차보다 훨씬 커서 안 흔들린다. **그래도 직선거리라 실제 도보는 1.2~1.4배**이므로 캐치테이블의 1m 단위("361m")를 따르지 않고 기존 `formatDistance`의 10m 반올림을 쓴다 — 좌표 오차 ±30m에 맞는 해상도이고 화면 1 카드 표기와도 같다.
- **임계값 800m는 데이터가 아니라 코드(`lib/data.ts`)가 갖는다**: JSON에는 사실(역·출구·미터·노선)만 굽고 컷은 파생에서 한다. 값을 바꿔도 재생성이 필요 없고 픽스처로 두 분기를 테스트할 수 있다. 목 기준 47/50이 걸리고 까치산 980m·고촌 1,022m(김포시 — "지방" 케이스)·화곡 1,087m가 주소만 남는다.
- **출처는 OpenStreetMap / Overpass (ODbL, 키 불필요)**. 역 621 + 정차점 5,856 + 출구 2,757개(≈3.6MB)를 클라이언트 번들에 올리지 않고 `scripts/add_nearest_station.py`가 `places.json`에 결과만 굽는다(+414줄). 좌표·주소와 같은 성격의 시드 시점 외부 파생 사실이고, Phase 6에선 서버 쓰기 시점에 채우는 컬럼이 될 자리다. **후속 과제**: 실서비스 전 공공데이터(국토부 역사 표준데이터, 공공누리 1유형)로 재생성 — 스크립트의 fetch 함수 3개만 교체.
- **실측으로 깨진 접근 4개(다시 시도하지 말 것)**:
  1. **호선을 역 `ref`(역번호)에서 뽑기** — 최근접 50곳 중 32곳에 `ref`가 없다. 노선 릴레이션을 거쳐야 50/50이 된다.
  2. **릴레이션 멤버를 `node(r)["railway"="station"]`로 받기** — 한국 노선 릴레이션의 멤버는 역 노드가 아니라 승강장 정차점(`railway=stop`)이라 전부 걸러져 빈 결과가 나온다. 멤버를 통째로 받아 **역이름 일치 + 400m 이내**로 잇는다.
  3. **Wikidata P81을 노선 출처로 쓰기** — 운행 노선이 아니라 "경부선·용산선" 같은 시설 노선이 나오고 색도 항목마다 불일치. 좌표 교차검증에만 쓴다.
  4. **역 이름으로 중복 제거** — 같은 이름 다른 위치가 실재한다(신촌 2호선↔경의중앙선 **704m**, 수서 360m, 청량리 327m). 노드를 그대로 두고 최근접을 고르면 이름이 저절로 맞는다.
- **데이터 정제 규칙 2개**: 출구 `ref`에 `"엘리베이터"`·`"한강진역 2번출구"` 같은 오염 값이 섞여 있어 `^\d{1,2}(-\d)?$`만 채택한다(아니면 역 중심 거리로 폴백). 역명이 이미 "역"으로 끝나는 경우(`서울역`)에 "역"을 또 붙이지 않는다. 괄호 이름 `총신대입구(이수)`는 공식 표기라 그대로 둔다.
- **표시 문법**: 노선색 20px 원(흰 숫자 12/600) + 역명 + 출구 + 거리. 환승역은 **숫자 호선을 전부** 나란히 놓고(서울 최대 3개) 개수를 고정하지 않는다. **숫자가 없는 노선(수인·분당, 김포 골드라인 — 목 4/50)은 배지 없이 역명만** 쓴다: 원 안에 넣을 숫자가 없고 한글 약자("수")는 관습이 아니며, 색 원만 그리면 의미를 못 읽는다. 아이콘은 붙이지 않는다("아이콘은 액션에만" 원칙, coolicons에 지하철 아이콘이 아예 없기도 하다 — `ci` 715개 중 0건).
- **보라색 금지 규칙의 예외**: 5호선 #794698은 우리가 고른 색이 아니라 **사실 표기**라 그대로 쓴다. 20px 배지 안에서만이고 브랜드 레드 1개 원칙·카드 색 띠 금지는 그대로다. 토큰도 Semantic 역할 없이 Primitive `subway-1`…`-9` 9개로 닫는다(숫자 호선만 배지를 그리므로 더 늘지 않는다).
- **배지는 `aria-hidden`, 호선은 `sr-only` 텍스트로 읽힌다**: 9호선 #A49D87 위 흰 숫자는 대비 2.4:1이다. 색은 보조 신호고 정보는 텍스트가 갖는다.
- **한 줄 폭 규칙과 출구 생략 폴백**: 320에서 이 줄이 쓰는 폭은 265px(Playwright 실측). 넘치면 **출구만 떼서** `동대문역사문화공원역에서 990m`로 줄인다 — 출구 없는 형태는 서울 최장 역명 + 배지 3개(실측 259.4px)에서도 들어간다. 판정은 브라우저 측정이 아니라 문자 폭 근사(`estWidth`)로 해서 Vitest로 검증한다. **근사는 실측보다 0.8~3.4px 작게 나오므로 예산을 265가 아니라 259로 잡는다**(플랜은 과대추정이라고 적었는데 실측이 반대였다 — 265 그대로면 `총신대입구(이수)역 5번출구에서 320m` 추정 265 / 실측 265.8이 통과했다가 잘린다). 뷰포트마다 다르게 판정하지 않고 320 기준 하나로 통일한다: 390에서만 출구가 나타났다 사라지면 더 이상하다. 현재 목 50곳은 전부 출구를 유지하고(최악 가산디지털단지 255), 마지막 안전망으로 `truncate`를 건다.
- **도로명을 `fg-secondary`로 낮췄다**: 서울에서는 "어느 역 근처냐"가 도로명보다 먼저 읽힌다. 역 줄(fg) → 도로명(fg-secondary) → 지번(fg-tertiary) 3단이고, 간격은 역↔도로명 2로 "여기가 어디냐" 한 묶음이다. 역 줄은 복사 버튼이 붙은 flex 행 **바깥**의 독립 문단이다 — 안에 넣으면 `items-start`가 복사 버튼을 역 줄 옆에 붙여 "역을 복사"로 읽힌다.
- **Overpass 운영 메모**: 태그 조합을 서버에서 union하면 504가 난다(역 질의는 통째로 받아 파이썬에서 거른다). 지하철·경전철과 일반철도 릴레이션은 한 질의에 넣으면 타임아웃 — 두 번으로 쪼갠다. 스크립트는 `--cache`로 응답을 재사용하고, 재실행 결과가 바이트 단위로 같다(idempotent).
