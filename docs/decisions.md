- **맥락**: DAU 2천 서비스가 월 $86 청구된 실사례 분석 (Threads @kindainvestor). 원인은 트래픽이 아니라 **ISR 남용**: `revalidate: 60` × 동적 URL 9,649개 → 재생성마다 Function Duration + ISR Writes 이중 과금. 부가 요인: next.config `headers()`의 Cache-Control이 페이지 `revalidate`를 덮어써 s-maxage=60 고정(두 번 배포하고 발견), 크롤러 트래픽, Observability 과금.
- **우리 방어선 (Phase 5~6에서 지킬 것)**:
  1. **페이지 캐시는 on-demand 우선**: 쓰기(제보·다녀왔다면·리뷰)가 우리 앱을 거치므로 `revalidateTag`/`revalidatePath`로 변경 시에만 재생성. 주기 revalidate는 보조로 3600s 이상. **`revalidate: 60` 같은 분 단위 금지** — 우리 데이터는 분 단위 신선도가 필요 없다.
  2. **next.config `headers()`에 페이지 경로 Cache-Control 금지** — 페이지 revalidate를 무력화한다. 폰트·정적 자산(`/fonts/*` 등)만 허용.
  3. URL 규모 자각: /place/[id] 452 + /gu/[name] 25 ≈ 477개 (그 사례의 1/20). on-demand면 재생성은 실제 데이터 변경 횟수에 비례.
  4. Observability Plus 켜지 않는다.
  5. **Hobby 플랜 유지** — 한도 초과 시 과금이 아니라 정지라 요금 폭탄이 구조적으로 불가능. Pro 전환 시 Spend Management 지출 상한을 반드시 같이 설정.
  6. 폰트는 dynamic subset (아래 결정).
- **재검토 조건**: Pro 전환 시, 또는 Phase 5 SSR 페이지 추가 시 이 목록 재확인.

- **빈 상태 ＋ 타일만 176 → 112 폭**(2026-09-03 저녁, 320 실측 후): 타일이 176이면 320에서 오른쪽 안내 열이 49px밖에 안 남아 "첫 사진을 올려주세요"(113px)가 네 줄로 접힌다. **불변식은 "행 높이가 같다"이지 "폭이 같다"가 아니다** — 높이 128은 그대로 두고 폭만 좁혔다(280 − 112 − 12 − 12 − 16 = 128 ≥ 113). 사진이 있는 스트립의 타일과 끝 ＋ 타일은 176 그대로(빈 상태와 나란히 보이는 일이 없다).
- **사진 상한 10장**(`MAX_PLACE_PHOTOS`, lib/data.ts). UI 상수가 아니라 도메인 규칙이라 데이터 계층에 두고 변환에서 `slice`로 막는다. 근거: 한 가게에 필요한 건 음식·간판·내부 정도고, 익명 업로드라 상한이 없으면 도배가 가장 싼 공격이다.
- **데이터 모양 `photoUrls: string[]` → `photos: Photo[]`**(`{ id, url, uploadedAt }`). 업로드 날짜를 보여주려면 배열 원소가 문자열일 수 없다. 이름을 그대로 두면 필드가 거짓말이 되므로 개명했다(참조처 7곳). **`thumbnailUrl = photos[0]?.url ?? null` 파생은 유지** — 카드·마커는 무변경. 목 단계의 `id`는 `{placeId}-p{n}` 파생이고 Phase 6에서 DB uuid로 바뀐다.
- **뷰어는 네이티브 `<dialog>` + `showModal()` + body 포털**. 이유 둘: (1) `.saeu-sheet`가 `transform: translateY()`라 시트 안의 `position: fixed`는 뷰포트가 아니라 시트를 기준으로 잡힌다 — 전체 화면이 안 나온다. (2) top layer는 z 경쟁(시트 z-20, 드롭다운 z-30, 토스트 z-10) 자체를 없애고 포커스 트랩·`inert`·Escape·포커스 복원을 공짜로 준다. 대가는 jsdom에 `showModal`이 없어 `vitest.setup.ts`에 스텁 4줄.
- **좌우 넘김은 CSS scroll-snap, JS 제스처 없음**. 바텀시트가 겪은 pointer-capture 리타겟·non-passive touchmove 함정은 전부 "세로 시트 vs 가로 스트립" 경합에서 나온 것인데, 포털된 단독 표면에는 그 경합이 없다.
- **뒤로가기**: 뷰어를 열 때 `history.pushState({saeuDetail:true, saeuPhoto:true}, "", location.pathname)` — **URL은 바꾸지 않는다**(바꾸면 `use-map-screen`의 `PLACE_PATH` 재동기화가 깨지고, 사진 인덱스는 아직 공유할 자원이 아니다). ⚠︎ **`openDetail` 멱등 가드가 이 설계의 전제다** — pathname이 그대로라 뷰어를 닫을 때 popstate가 같은 id로 `openDetail`을 다시 부르고 `setSnap("half")`가 실행돼 **전체로 펼쳐 둔 시트가 요약으로 튄다**. 같은 id면 no-op으로 막는다.
- **뒤집은 결정 — 신고는 "준비 중이에요" 토스트가 아니다**(2026-09-02 미구현 입구 목록). **사진 신고만** 사유 선택 + 목 저장까지 실제로 동작한다(가게 신고·리뷰 신고는 그대로 토스트). 이유: 신고는 다른 미구현 입구와 성격이 다르다 — 나머지는 "아직 못 만든 편의 기능"이지만, 익명 업로드 이미지에 대한 신고는 **없으면 안 되는 안전장치**다. 사유 4개(부적절한 사진/다른 가게 사진/광고·도배/기타), **행 탭이 곧 제출**이라 확인 버튼이 없다 — 고르고도 안 낸 상태를 만들지 않는다(네이버·인스타 신고 시트의 문법).
- **실패 토스트는 뷰어 안에 따로 렌더한다.** 기존 토스트는 z-10이라 top layer 아래에 무조건 가리고, 신고 실패 시에는 뷰어를 닫으면 안 된다(무엇이 실패했는지 사라진다). 성공만 뷰어를 닫고 기존 토스트를 쓴다. 타이머 호출자가 셋이 되면 `lib/use-notice.ts`로 승격한다.
- **새 토큰 4개**: `bg-immersive`(common-100) · `fg-on-immersive`(common-0) — 딤·몰입 표면 Semantic 자리가 비어 있었다. 여기에 `bg-immersive-raised`(gray-800) · `fg-on-immersive-secondary`(gray-400)를 더했다(아래 항목).
- **뷰어 chrome 재조정**(같은 날, 실제 화면을 보고): 날짜·[신고]가 12 맨 텍스트라 **작고 떠 있었다** — [신고]의 실측 탭 영역이 20×17px로 44px 기준에 한참 못 미쳤다. 날짜는 14 medium + 회색 " 등록"(그냥 날짜만 있으면 무슨 날짜인지 모른다), [신고]는 아이콘 16 + 14 medium의 **44px 알약**, 상단 ✕·카운터도 같은 알약 표면으로 통일. 근거 둘: (1) 탭 영역 44px은 타협 대상이 아니다, (2) 흰 접시 사진이 뒤에 오면 맨 흰 아이콘·글자는 배경과 같은 색이 된다 — 몰입 표면의 컨트롤에는 자기 배경이 필요하다(인스타·네이버 뷰어의 문법). 알약 색은 브랜드 레드가 아닌 gray-800이라 "채운 레드는 화면당 한 곳" 규칙과 무관하다.

## 2026-09-03 — 상세 요약 높이 50% → 30%(최소 270px)

- **결정**: 상세 시트의 기본 스냅을 `max(50dvh, 300px)` → **`max(30dvh, 270px)`**. 요약에서 보이는 것은 사진 스트립 + 상호 블록(상호·카테고리·**"3일 전 확인"**)까지고, 정보 블록·버튼 줄은 본문 스크롤이나 전체 펼침으로 본다.
- **이유**: 사용자 피드백 — "지도를 너무 가리는 느낌". 지도 화면에서 시트가 화면 절반을 먹으면 **정작 지도가 보조가 된다**. 2026-09-02 항목의 재검토 조건("요약 높이 50%는 사용감 피드백 시")이 그대로 발동한 경우다.
- **하한 270px은 임의값이 아니다**: 헤더 44 + 사진 144 + 상호 블록 = 확인 캡션 바닥 **257px**(320·390, 긴 상호 포함 실측 동일 — 상호는 1줄 truncate) + 바닥 여백 13. 30dvh만 쓰면 844에서 253px이라 캡션이 4px 잘리므로 `max()`의 하한이 실제로 이기는 값이다(1000px 이상 뷰포트에서만 30%가 이긴다).
- **뒤집은 결정**: 2026-09-02 "요약 상태 정의 = 50dvh(최소 300px)", 2026-09-03 "요약에서 4번 버튼 줄까지 보이는 것이 수용 기준"(사진 176×128 항목). **사진 타일 크기는 그대로 둔다** — 높이 예산이 더는 버튼 줄에 묶여 있지 않으므로 128을 112로 내릴 이유가 사라졌다. 320×568에서 [길찾기]가 접히던 것도 이제 결함이 아니라 정의된 동작이다.
- **주 액션이 접히는 대가**: [길찾기](채운 레드)가 요약에서 안 보인다. 받아들이는 근거는 (1) 상세를 연 직후의 판단 재료는 사진·상호·신선도이고, 길찾기는 그 판단 **뒤**에 오는 액션이며, (2) 본문이 스크롤 컨테이너라 요약에서도 손가락 한 번이면 닿는다(스크롤 체이닝). 네이버지도·카카오맵도 첫 스냅은 이름·거리·신선도까지다.
- **재검토 조건**: 길찾기 도달률이 문제가 되면 요약 높이가 아니라 **요약 상태의 고정 액션 바**(시트 하단에 겹치는 줄)를 검토한다 — 높이를 되돌리지 않는다.

- **정확도(직접 물어서 답한 값)**: ① 역 좌표는 Wikidata(CC0, 독립 소스) 대조 편차 중앙값 21m·평균 31m, 100m 이내 46/47, 최대 145m(옥수). ② 가게 좌표는 독립 지오코딩으로 건물이 특정된 4곳에서 1·4·4·24m(동피랑 1m, 동강해물찜 4m — 상호까지 일치). ③ "어느 역이냐"는 1위↔2위 격차 중앙값 406m(최소 44m)로 좌표 오차보다 훨씬 커서 안 흔들린다. **그래도 직선거리라 실제 도보는 1.2~1.4배**이므로 캐치테이블의 1m 단위("361m")를 따르지 않고 기존 `formatDistance`의 10m 반올림을 쓴다 — 좌표 오차 ±30m에 맞는 해상도이고 화면 1 카드 표기와도 같다.
- **임계값 800m는 데이터가 아니라 코드(`lib/data.ts`)가 갖는다**: JSON에는 사실(역·출구·미터·노선)만 굽고 컷은 파생에서 한다. 값을 바꿔도 재생성이 필요 없고 픽스처로 두 분기를 테스트할 수 있다. 목 기준 47/50이 걸리고 까치산 980m·고촌 1,022m(김포시 — "지방" 케이스)·화곡 1,087m가 주소만 남는다.
- **출처는 OpenStreetMap / Overpass (ODbL, 키 불필요)**. 역 621 + 정차점 5,856 + 출구 2,757개(≈3.6MB)를 클라이언트 번들에 올리지 않고 `scripts/add_nearest_station.py`가 `places.json`에 결과만 굽는다(+414줄). 좌표·주소와 같은 성격의 시드 시점 외부 파생 사실이고, Phase 6에선 서버 쓰기 시점에 채우는 컬럼이 될 자리다. **후속 과제**: 실서비스 전 공공데이터(국토부 역사 표준데이터, 공공누리 1유형)로 재생성 — 스크립트의 fetch 함수 3개만 교체.
- **실측으로 깨진 접근 4개(다시 시도하지 말 것)**:
  1. **호선을 역 `ref`(역번호)에서 뽑기** — 최근접 50곳 중 32곳에 `ref`가 없다. 노선 릴레이션을 거쳐야 50/50이 된다.
  2. **릴레이션 멤버를 `node(r)["railway"="station"]`로 받기** — 한국 노선 릴레이션의 멤버는 역 노드가 아니라 승강장 정차점(`railway=stop`)이라 전부 걸러져 빈 결과가 나온다. 멤버를 통째로 받아 **역이름 일치 + 400m 이내**로 잇는다.
  3. **Wikidata P81을 노선 출처로 쓰기** — 운행 노선이 아니라 "경부선·용산선" 같은 시설 노선이 나오고 색도 항목마다 불일치. 좌표 교차검증에만 쓴다.
  4. **역 이름으로 중복 제거** — 같은 이름 다른 위치가 실재한다(신촌 2호선↔경의중앙선 **704m**, 수서 360m, 청량리 327m). 노드를 그대로 두고 최근접을 고르면 이름이 저절로 맞는다.
- **데이터 정제 규칙 2개**: 출구 `ref`에 `"엘리베이터"`·`"한강진역 2번출구"` 같은 오염 값이 섞여 있어 `^\d{1,2}(-\d)?$`만 채택한다(아니면 역 중심 거리로 폴백). 역명이 이미 "역"으로 끝나는 경우(`서울역`)에 "역"을 또 붙이지 않는다. 괄호 이름 `총신대입구(이수)`는 공식 표기라 그대로 둔다.
- **표시 문법**: 노선색 16px 원(흰 숫자 12/600 — 처음 20px로 넣었다가 같은 날 축소, 아래 "정보 블록 미세 조정" 항목) + 역명 + 출구 + 거리. 환승역은 **숫자 호선을 전부** 나란히 놓고(서울 최대 3개) 개수를 고정하지 않는다. **숫자가 없는 노선(수인·분당, 김포 골드라인 — 목 4/50)은 배지 없이 역명만** 쓴다: 원 안에 넣을 숫자가 없고 한글 약자("수")는 관습이 아니며, 색 원만 그리면 의미를 못 읽는다. **지하철 아이콘은 coolicons에 아예 없다**(`ci` 715개 중 train/subway/metro/rail 0건) — 배지 자체가 노선 표지라 근접 대체도 두지 않는다. (정보 블록 앞의 핀·시계 아이콘 열은 같은 날 추가했다 — 아래 "정보 블록 미세 조정" 항목.)
- **보라색 금지 규칙의 예외**: 5호선 #794698은 우리가 고른 색이 아니라 **사실 표기**라 그대로 쓴다. 16px 배지 안에서만이고 브랜드 레드 1개 원칙·카드 색 띠 금지는 그대로다. 토큰도 Semantic 역할 없이 Primitive `subway-1`…`-9` 9개로 닫는다(숫자 호선만 배지를 그리므로 더 늘지 않는다).
- **배지는 `aria-hidden`, 호선은 텍스트로 읽힌다**: 9호선 #A49D87 위 흰 숫자는 대비 2.4:1이다. 색은 보조 신호고 정보는 텍스트가 갖는다. (수단은 `sr-only` 조각 → 헤더 버튼 `aria-label`로 같은 날 교체 — 아래 "정보 블록 미세 조정" 항목.)
- **한 줄 폭 규칙과 출구 생략 폴백**: 320에서 이 줄이 쓰는 폭은 265px(Playwright 실측). 넘치면 **출구만 떼서** `동대문역사문화공원역에서 990m`로 줄인다 — 출구 없는 형태는 서울 최장 역명 + 배지 3개(실측 259.4px)에서도 들어간다. 판정은 브라우저 측정이 아니라 문자 폭 근사(`estWidth`)로 해서 Vitest로 검증한다. **근사는 실측보다 0.8~3.4px 작게 나오므로 예산을 265가 아니라 259로 잡는다**(플랜은 과대추정이라고 적었는데 실측이 반대였다 — 265 그대로면 `총신대입구(이수)역 5번출구에서 320m` 추정 265 / 실측 265.8이 통과했다가 잘린다). 뷰포트마다 다르게 판정하지 않고 320 기준 하나로 통일한다: 390에서만 출구가 나타났다 사라지면 더 이상하다. 현재 목 50곳은 전부 출구를 유지하고(최악 가산디지털단지 255), 마지막 안전망으로 `truncate`를 건다. (같은 날 핀·chevron이 44px을 먹으면서 예산은 **217**로 재도출됐고 가산디지털단지 2곳이 폴백에 들어갔다 — 아래 "정보 블록 미세 조정" 항목.)
- **도로명을 `fg-secondary`로 낮췄다**: 서울에서는 "어느 역 근처냐"가 도로명보다 먼저 읽힌다. 역 줄(fg) → 도로명(fg-secondary) → 지번(fg-tertiary) 3단이고, 간격은 역↔도로명 2로 "여기가 어디냐" 한 묶음이다. 복사 버튼은 역 줄이 아니라 도로명 행에 붙는다 — 역 줄과 같은 flex 행에 넣으면 `items-start`가 버튼을 역 줄 옆으로 올려 "역을 복사"로 읽힌다. (같은 날 주소를 드롭다운으로 접으면서 [복사]는 펼친 패널 안으로 들어갔다 — 아래 "정보 블록 미세 조정" 항목.)
- **Overpass 운영 메모**: 태그 조합을 서버에서 union하면 504가 난다(역 질의는 통째로 받아 파이썬에서 거른다). 지하철·경전철과 일반철도 릴레이션은 한 질의에 넣으면 타임아웃 — 두 번으로 쪼갠다. 스크립트는 `--cache`로 응답을 재사용하고, 재실행 결과가 바이트 단위로 같다(idempotent).

## 2026-09-03 — 상세 정보 블록 미세 조정: 아이콘 열·16px 배지·접히는 주소·지번 축약

캐치테이블 상세 스크린샷을 다시 대조하고 같은 날 넣은 역 줄을 네 군데 고쳤다.

- **"아이콘은 액션에만" 규칙을 정보 블록에서 뒤집는다**(design.md의 그 줄도 같이 고쳤다). 위치 그룹 앞에 핀(`ci--location`), 영업시간 앞에 시계(`ci--clock`) 16px을 세운다. 근거 두 개: ① 값이 4종(역·도로명·지번·영업시간)으로 늘면서 "이게 어떤 값이냐"를 회색 계층만으로는 못 구분한다 — 아이콘은 장식이 아니라 **행의 종류를 가리키는 인덱스**다. ② 접힌 주소가 핀 아래로 들여쓰기되려면 **정렬 기준**이 필요하다(아이콘 열 22px = 16 + gap 6). 값 앞의 체크·별 같은 순수 장식 아이콘은 여전히 금지다.
- **배지 20px → 16px(`size-4`)**. 20px은 14px 글자의 행 높이(19.6px)를 꽉 채워 배지가 탭할 수 있는 버튼처럼 보였다. 16px이면 글자보다 확실히 작아 "역 이름에 붙은 표지"로 읽힌다. 숫자는 12/600 그대로다(원이 작아져도 두 자리가 들어갈 일은 없다 — 숫자 호선은 1~9).
- **주소는 기본 접힘, 역 줄이 그 disclosure의 헤더다.** 도로명+지번이 상시 두 줄을 먹을 이유가 없다 — 주소는 길찾기·복사할 때만 쓰는 값이고, 서울에서 먼저 읽히는 위치 정보는 역이다. 역 줄 오른쪽에 chevron ⌄(펼치면 180° 회전, Tailwind v4에서 `rotate-180`은 `transform`이 아니라 `rotate` 프로퍼티라 계산값은 `rotate: 180deg`로 확인한다), 펼치면 도로명·지번·[복사]가 핀 아래로 들여쓰기돼 나온다.
- **역이 없으면(800m 밖) chevron도 없고 주소가 그냥 보인다.** 헤더와 본문이 같은 disclosure는 만들지 않는다 — 누를 대상이 없는데 접는 것은 상태만 늘린다. 이때 도로명도 `fg-secondary`를 유지한다: 정보 블록에서 진한 값(fg)은 "가장 먼저 읽히는 하나"(역 줄)뿐이고, 같은 필드가 케이스마다 다른 무게를 갖는 게 더 나쁘다.
- **"주소가 왜 두 개냐"는 표기 문제였다**(도로명·지번 둘 다 필요한 값이라 지우지 않았다). 원인 두 개를 각각 고쳤다: ① 둘이 항상 같이 보였다 → 드롭다운으로 접었다. ② 지번이 `"서울 송파구 가락동 600"`처럼 시·구까지 달고 나와 바로 위 도로명과 접두어가 겹쳤다 → **동·번지만 남긴다**(`shortJibun`: `(동|가|리|읍|면)\d*가?$`로 법정동을, `^산?\d+(-\d)?$`로 번지를 찾는다). 뒤에 붙은 건물명·층(`"… 400-1 금강리빙스텔 2층 팔팔수산"`)은 지번이 아니라 크롤링 잔재라 같이 자른다. **형식을 못 읽으면 원문을 그대로 둔다** — 모르는 형식을 잘라 틀린 주소를 만드는 것보다 길게 두는 게 낫다. 복사되는 값은 손대지 않은 도로명 원문이다.
- **한 줄 예산 259 → 217 재도출.** 핀(16+6)과 chevron(16+6)이 44px을 먹는다: 265(320 실측 콘텐츠 폭) − 22 − 22 − 4(폭 근사의 관측 최대 과소분 3.4 올림) = **217**. 그 결과 8자 역명 + 배지 2개가 걸려 **가산디지털단지역 2곳**(p261·p268)이 출구를 뗀 폴백으로 내려갔다 — 전수 계산으로 확인한 유일한 2곳이고 최종 폭 216/217이다. 10자 역명 + 배지 3개(동대문역사문화공원역)는 **폴백도 예산을 넘어** `truncate`가 받는다: 서울에 그 조합이 이 역 하나뿐이라 폴백 사다리를 더 만들지 않는다. 실측(320/390/430)에서 표시되는 47곳 전부 한 줄이고 잘림 0건이다.
- **호선 낭독은 `sr-only` 조각이 아니라 헤더 버튼의 `aria-label`로 한다.** 접근 이름 계산(dom-accessibility-api)은 자식 요소의 기여를 각각 trim한 뒤 **구분자 없이 이어 붙인다** — `sr-only` "9호선" + 라벨이 `"9호선송파나루역 2번출구에서 370m"`으로 읽혔다(span 안에 공백을 넣어도 trim된다). 버튼에 `aria-label={["3호선","8호선", 라벨].join(" ")}`을 주면 문장으로 읽힌다. 배지는 `aria-hidden` 그대로.
- **스켈레톤에 주소 자리를 두지 않는다**: 기본이 접힘이라 실제 화면도 아이콘 열 + 값 두 줄(역·영업시간)이다.

## 2026-09-03 — 상호 블록은 3줄 유지 (구 삭제·확인 캡션 승격 검토 후 기각)

주소를 드롭다운으로 접은 직후 "`생새우회 · 송파구`에서 구를 빼고 그 자리에 `3일 전 확인 · 확인 0회`를 올리자"를 검토했고 **현재 형태를 유지**한다.

## 2026-09-03 — 사진 뷰어는 dialog를 열고 나서 첫 슬라이드를 잡는다 (Codex PR #5 P1·P2)

- **`showModal()`과 첫 위치 지정은 한 layout effect 안에서 이 순서로.** 열기가 passive effect(`useEffect`)에, 위치 지정이 `useLayoutEffect`에 나뉘어 있으면 React가 layout effect를 먼저 흘린다. 그때 dialog엔 `open`이 없어 `display:none`이라 트랙의 `clientWidth`가 0이고 `scrollLeft = 0 × n = 0`이다. 스크롤이 안 났으니 `syncIndex`도 안 돌아 **화면은 1번 사진인데 카운터·등록일·신고 대상만 고른 사진**을 가리켰다(스트립 2번째 이후 전부).
- **이 회귀는 dev에서 안 보인다.** App Router는 StrictMode가 기본이라 effect를 두 번 돌리고, 두 번째 layout effect는 첫 passive effect(=`showModal()`) **뒤에** 실행돼 `clientWidth`가 잡힌다. effect 순서 버그는 `pnpm build && pnpm start`로만 판정한다. 계측(`scrollLeft` setter + `showModal` 후킹)으로 순서를 직접 봤다: 수정 전 `set 0(cw 0, open false) → showModal`, 수정 후 `showModal → set 780(cw 390, open true)`.
- **같은 포트에 남은 이전 빌드 청크를 브라우저가 재사용한다.** 고친 뒤 같은 포트에서 다시 재니 버그가 그대로 나왔는데 번들 원본엔 수정이 들어 있었다 — `rm -rf .next` + **새 포트**로 재야 맞는 값이 나온다. 프로덕션 재검증은 포트를 바꿔서 한다.
- jsdom은 `clientWidth`가 항상 0이라 이 버그를 구조적으로 못 잡는다(테스트 208개가 전부 통과한 채 나갔다). 검증은 Playwright + 프로덕션 빌드로: p025의 3·10·1번, p018의 3번에서 **보이는 슬라이드 = 누른 번호**.
- **지번 축약 폴백 보강**: 동은 찾고 번지를 못 찾으면(`경기 김포시 고촌읍`, `123번지` 표기) 끝까지 자르지 않고 **원문 그대로** 반환한다 — 바로 위 항목의 "형식을 못 읽으면 원문"이 반쪽만 구현돼 시·도가 조용히 사라지고 있었다. 목 49곳엔 해당 케이스 0건. 기존 테스트가 이름은 "원문 그대로"인데 단언은 `"고촌읍"`이라 **버그를 정답으로 고정**하고 있었다 — 문서가 맞고 코드·테스트가 틀린 경우다.

## 2026-09-04 — 키보드가 뜨면 시트가 그 위에 앉는다 (visualViewport)

실기기에서 제보 1단계 입력에 포커스하면 **[새로 등록하기] CTA와 캡션만 남고 위쪽이 전부 빈 흰 화면**이 됐다(사파리·네이버 인앱 스크린샷 2장). 타이핑 중인 입력 필드·제목·진행바가 사라진다.

- **원인**: 시트가 `position: fixed; bottom: 0; height: 92dvh`인데 키보드가 떠도 레이아웃 뷰포트(`innerHeight`·`dvh`)는 안 줄고 visual viewport만 줄어든다. 시트는 키보드 뒤에 남고, iOS가 포커스된 입력을 보이려고 visual viewport를 아래로 스크롤(`offsetTop`)하면서 시트 위쪽 내용이 화면 밖으로 밀려났다.
- **`window.visualViewport` 구독 하나로 iOS·안드로이드를 같이 덮는다.** `max(0, innerHeight - vv.height - vv.offsetTop)`을 `--kb`로 `:root`에 쓰고(`components/ui/use-keyboard-inset.ts`), `.saeu-sheet`가 `bottom: var(--kb)`로 키보드 위에 앉고 `--sheet-full: calc(92dvh - var(--kb))`로 그만큼 낮아진다. 안 낮추면 위가 화면 밖으로 넘친다. `height`·`transform`이 둘 다 `--sheet-full`을 쓰므로 스냅 계산은 그대로 맞는다.
- **뷰포트 meta의 `interactive-widget`은 쓰지 않는다.** Chrome 108+·Firefox 132+ 전용이라 **Safari에 없고**(WebKit 259770 오픈), 켜면 Chromium에서만 레이아웃 뷰포트가 줄어 **`h-dvh`인 지도까지 리사이즈된다** — 제보 2단계(주소 검색 + 지도)에서 타이핑마다 지도가 튀는 안드로이드 전용 부작용을 새로 만드는 셈이다. 안드로이드 기본값도 `resizes-visual`이라 증상이 iOS와 같으므로 visualViewport 하나면 양쪽이 다 고쳐진다.
- **높이는 `--kb`가 아니라 `--vvh`(보이는 창의 높이)로 정한다 — 첫 수정이 틀렸다.** 처음엔 `--sheet-full: calc(92dvh - var(--kb))`로 했는데, **iOS가 visual viewport를 끝까지 밀면 `offsetTop`이 키보드 높이와 같아져 `--kb`가 0이 된다**(795 − 459 − 336 = 0). 그때도 창은 키보드만큼 낮은데 시트만 92dvh로 남아 위로 272px 넘치고, 넘친 만큼 제목·입력이 화면 밖으로 밀린다 — **실기기에서 증상이 그대로였다.** `bottom`은 `--kb`가 맞지만 높이는 창 높이 자체를 써야 한다: `--sheet-full: calc(0.92 * var(--vvh, 100dvh))`.
- 검증(`--kb`·`--vvh` 주입, 두 상태 모두): `offsetTop 0`(kb 336)과 `offsetTop 336`(kb 0) **양쪽에서** 시트가 보이는 창 안에 들어가고 진행바·제목·입력·CTA가 전부 보인다. 헤드리스엔 가상 키보드가 없어 **실기기 확인이 완료 조건**이다.
- **알아 둘 것**: `--kb > 0`이면 CSS(`dvh`)와 JS(`window.innerHeight` 기반 `sheetVisiblePx`)가 갈린다. 위 "두 소스는 일치한다"는 판단의 전제를 이 변경이 깬다. 스냅 계산은 드래그할 때만 쓰이고 타이핑 중엔 드래그하지 않아 이번엔 두지만, 소스 통일 백로그의 근거가 하나 늘었다.
- **안드로이드는 미확인.** 지금까지의 측정·스크린샷이 전부 아이폰 하나에서 나왔다. 코드는 양쪽을 덮지만 동작 확인 전까지는 추정이다.

## 2026-09-04 — 제보 3단계: 필수는 캡션에서 한 번만, 회 줄은 켜면 포커스

- **필수 표시는 캡션 한 줄로.** spec 4.3이 "메뉴명·가격·단위 칩 한 줄(필수)"이라 3단계는 **세 필드가 전부 필수**고 4단계는 전부 선택이다. 즉 필수/선택이 이미 **단계 단위로 갈려 있어** 필드마다 `*`를 붙이면 셋 다 `*`라 정보량이 0이다. 캡션을 "대표 메뉴 한 줄이면 돼요. 이름·가격·단위를 모두 채워주세요"로 고친다. (실기기에서 "다 필수인가? 그래서 `*`를 안 붙인 건가?"라는 질문이 나왔다 — 지금까지는 [다음]을 눌러 오류가 떠야 알 수 있었다.)
- **"새우회도 팔아요"를 켜면 새우회 메뉴명에 포커스.** 회 줄이 토글 아래에 생기는데 스크롤 밖이라 안 보였다. `[마리]` 칩이 "몇 마리" 입력에 포커스하는 기존 방식과 같게 맞춘다 — 포커스가 가면 브라우저가 스크롤도 같이 해 준다.
- **마운트 이펙트로 하지 않는다.** `report-panel.tsx`가 `switch (step)`으로 단계를 **언마운트**하므로, rawToo가 켜진 채 ‹로 3단계에 돌아오면 그때마다 포커스를 뺏는다. "방금 켰다"는 신호를 토글 `onChange`에서 ref에 세우고 이펙트가 소비한다. **state가 아니라 ref인 이유**: state면 이펙트에서 되돌려야 하는데 그건 연쇄 렌더라 린트가 막는다(`Calling setState synchronously within an effect`). 정리(cleanup)에서 만지지 않으니 StrictMode 이중 effect에도 안전하다 — 첫 실행이 소비하고 두 번째는 지나간다.

## 2026-09-04 — 제보 CTA 위 스크롤 페이드 ("그라데이션 배경 금지"의 예외)

실기기에서 "CTA 윗부분이 좀 잘리는 느낌"이라는 지적. 본문 스크롤 컨테이너와 CTA 줄이 flex 형제라 경계에서 내용이 **뚝 잘린다**.

- **CTA 줄 위로 20px 페이드**(흰색 → 투명)를 얹는다. 본문 children 래퍼는 `pb-3` → `pb-6`으로 늘려, 끝까지 스크롤했을 땐 페이드가 **빈 자리만** 덮게 한다 — 마지막 항목이 흐려지지 않는다.
- **"그라데이션 배경 금지"(2026-09-02)의 예외로 둔다.** 그 규칙과 2026-09-03의 그라데이션 보더 기각은 **장식**을 막는 것이다(의미 없이 가장 시끄러운 요소가 되는 것). 이건 스크롤 끝을 부드럽게 하는 **기능적 마스크**라 성격이 다르다 — 지하철 노선색이 "사실 표기"라 보라 금지의 예외인 것과 같은 결. 색은 배경색(`--color-bg`) 한 가지에서 투명으로 갈 뿐 새 색을 들이지 않는다.
- **literal blur(`backdrop-filter`)는 쓰지 않는다.** 시트가 불투명 흰색이라 흰 위에 흰을 블러해도 거의 안 보인다. 그리고 blur를 쓰려면 CTA가 본문 위로 떠야 해서 본문 하단 패딩을 CTA 높이에 맞춰야 하는데, CTA 높이가 단계마다 달라 측정이 필요해진다. 흰색 → 투명 페이드가 같은 "부드럽게"를 더 싸게 만든다.
- **위쪽 끝은 안 했다(백로그).** 같은 결함이 스크롤 컨테이너 위쪽에도 있어 스크롤 중에는 제목이 글자 중간에서 잘린다. 다만 위에 그냥 페이드를 얹으면 **스크롤이 맨 위일 때 `‹` 버튼이 흐려진다** — 스크롤 위치를 보는 조건부라 JS가 필요하다. 아래쪽은 `pb-6` 여유 덕에 조건이 필요 없었다.

## 2026-09-04 — 현위치 마커 (spec에 없던 기능)

지도에 현위치 **버튼**(FAB)만 있고 **마커**가 없었다 — spec·design 어디에도 없어 미정이었다. 실기기에서 "일부러 안 넣은 건가?"라는 질문이 나왔고 넣기로 했다.

- `userLocation`은 `use-map-screen.ts`에 이미 있었다. 마커만 없어서 `getUserLocationIcon` + `<Marker>` 하나로 끝난다.
- **16px 파란 점 + 3px 흰 링.** 탭 대상이 아니라(`clickable={false}`) 히트 박스를 키우지 않고, `zIndex` 5로 가게 마커(100~300)보다 아래에 깔린다.
- **파랑은 브랜드 팔레트가 아니라 "내 위치"의 사실 표기다.** 네이버·카카오·구글이 다 쓰는 관습이라 설명 없이 읽힌다. 지하철 노선색이 보라 금지의 예외인 것과 같은 결이고, `locator` semantic 토큰 하나로 **이 마커 한 곳에만** 쓴다. 브랜드 레드로 하면 클러스터 마커(레드 원)·제보 핀과 헷갈린다.
- **최종은 새우 모양.** 에셋이 없어 표준 파란 점으로 대체하고 아래 커스텀 에셋 목록에 올린다.

## 2026-09-04 — 제보 1단계 "찾는 가게가 없나요?" 캡션 제거

버튼인 줄 알고 눌러 봤다는 지적에서 시작했다. 실제로는 [새로 등록하기]를 설명하는 12px 회색 캡션인데(design 화면 3 v1의 "빈 상태는 한 줄 + 인라인 액션"), 검색 결과가 5행 떠 있어도 같이 보여 문맥이 어긋나고 버튼과 떨어진 별개 액션처럼 읽혔다.

- **"매치가 없을 때만 보이기"로 먼저 고쳤다가 그것도 폐기했다.** 그 조건에서는 **아직 아무것도 검색하지 않은 빈 입력 상태에서도** 캡션이 뜬다 — 패널을 막 열었는데 "찾는 가게가 없나요?"가 먼저 말을 거는 셈이라, 정작 필요한 순간(쳐 봤는데 없을 때)보다 엉뚱한 순간에 더 자주 보인다.
- **그냥 뺀다.** `새로 등록하기`라는 라벨이 이미 무엇을 하는지 다 말한다. 시트 세로가 빠듯한데(실기기 656~702px, 키보드가 뜨면 더) 캡션 + 여백이 28px을 먹는다. 코드 최소주의 사다리 1("이게 꼭 있어야 하나").
- **CTA는 매치 유무와 무관하게 늘 있다** — 매치가 있어도 "그중엔 없다"며 등록할 수 있어야 한다.
- design 화면 3의 규칙을 "빈 상태는 한 줄 + 인라인 액션" → **"빈 상태는 액션 하나"**로 고친다.
