## [화면 1] 지도 메인

위 공통 블록에 이어서:

풀스크린 지도 위에 **두 층만** 얹힌 메인 화면. 지도는 밝은 회색 톤 플레이스홀더(네이버지도 느낌)로 두고 마커만 표시.

위에서 아래로:
1. 검색 블록 — 상태바 아래 흰 배경 블록 안에 회색(gray-100) 입력 하나: 돋보기 + "가게·동네 검색". 로고·버튼 없음. 블록 아래 옅은 그림자.
2. 칩 행 — 블록 아래 10px, 지도 위에 떠 있는 pill 한 줄: **[전체 ▾] 드롭다운 칩**(누르면 아래에 흰 카드 목록 전체 / 새우구이 / 생새우회, 선택하면 칩이 레드 틴트 "새우구이 ▾") + 토글 pill 5개 [머리버터구이] [라면] [볶음밥] [새로 들어온 집] [찜한 곳](흰 아웃라인, 켜면 틴트, AND). 칩 행 전체가 넘치면 함께 가로 스크롤(드롭다운 칩도 같이 넘어감). 사이드 칩을 켰는데 0곳이면 시트에 "조건에 맞는 집이 없어요 · 칩을 풀거나 지도를 옮겨보세요" + [필터 해제].
3. FAB 줄 — 바텀시트 가장자리 바로 위: **왼쪽** 흰 원(40px) 현위치 버튼(표적 모양 아이콘), **오른쪽** [＋ 제보] 레드 pill(화면의 유일한 채운 레드).
4. 바텀시트(화면 40% 올라온 상태) — 상단 라운드 20, 위로 뜨는 옅은 그림자, 핸들(50×6 회색). 헤더 한 줄: 제목 "마포구 일대 12곳"(20 semibold) 왼쪽 + 정렬 텍스트 트리거 "가까운순 ▾"(14 회색, 누르면 작은 목록) 오른쪽. 그 아래 캡션(12 회색): 초록 라이브 점 + "오늘 6건 확인됐어요 │ 이번 주 47곳"(구분은 세로 헤어라인, 숫자만 진하게). 아래 헤어라인.
5. 이벤트 행 — 시트 본문 맨 위, 공지 행 문법: 왼쪽 32px 레드 틴트 원 안 선물 아이콘 + 제목 "새우 까주기 테스트"(14 semibold) / 부제 "당신은 까주는 쪽?"(12 회색) + 오른쪽 닫기 × 하나. 행 전체가 링크(화살표 없음), 아래 헤어라인. em dash·가운데 점 같은 기호로 문장을 잇지 않는다.
6. (정렬 세그먼트는 없음 — 헤더 트리거로 대체)
7. 카드 리스트(2.5장 보임, 헤어라인 구분) — 카드 한 장: **왼쪽 64px 라운드 12 썸네일**(사진 없으면 회색 타일 가운데 카테고리 색점 — 마커 플레이스홀더와 같은 톤) + 오른쪽: 상호(16 semibold) / 오른쪽 끝 "어제 확인"(12 회색) / 메타 "**850m** · 마포구 · 새우구이 · 생새우회"(12 회색, 거리만 진하게 — 내 위치 없으면 지도 중심 기준) / 사이드 미니 pill(머리버터구이·라면). 메뉴·가격·평점은 카드에 없음(가격은 상세, 평점은 리뷰 3개 이상일 때만 나중에). 수성2호에는 "새로 제보됨" 레드 틴트 라벨.
8. 지도 마커 — 멀리: 레드 원 안에 가게 수("20"). 가까이: 36px 원에 가게 썸네일 + 카테고리색 링(코랄 5·틸 2), 썸네일 없으면 회색 원 안 카테고리 색점. 그중 1개는 점선 링(새로 제보됨), 하나는 선택 상태(확대 + 잉크 링).

샘플 데이터의 나라수산, 365활새우 창우수산, 수성2호를 카드로.

## [화면 2] 가게 상세 (바텀시트: 탭=요약, 드래그=전체, 스와이프=닫기)

위 공통 블록에 이어서:

지도 메인에서 카드나 마커를 탭하면 **같은 바텀시트**의 내용이 목록에서 상세로 바뀐다. 처음엔 **요약**(화면 높이의 30%, 최소 270px)으로 열리고, 위로 드래그하거나 핸들을 탭하면 **전체**(92%)로 펼쳐진다. 요약에서 본문을 위로 끌면 그대로 전체로 이어지고(스크롤 체이닝), 전체에서 맨 위를 아래로 끌면 요약으로 돌아온다. 요약에서 아래로 스와이프하면 닫히고 목록으로 돌아간다(목록은 있던 높이·스크롤 그대로). 공유 링크 `/place/[id]`로 들어오면 이 화면이 요약 상태로 열려 있다. 상세가 열린 동안 FAB 줄(현위치·제보)은 숨긴다. 지도는 해당 핀이 시트에 가려지지 않게 가시 영역 중앙으로 옮기고 핀은 선택 상태(확대 + 잉크 링).

시트 헤더(44px)는 핸들(50×6) + **오른쪽 닫기 ×**뿐이다. 상호가 아니라 시트 크롬에 있어 사진 유무·스크롤 위치와 무관하게 늘 같은 자리다. 좌우 여백 20·상단 라운드 20은 화면 1과 같다.

**이 화면의 채운 레드는 4번 [길찾기] 한 곳.** 카테고리 색은 쓰지 않는다(상세 안에서는 텍스트 태그). 섹션 사이는 8px 가라앉은 띠(bg-dim). UI 문장을 em dash·가운데 점으로 잇지 않는다(카드처럼 메타를 나열할 때만 가운데 점).

**이 화면의 디자인 규칙**(2026-09-03 리디자인 — 균일한 리듬이 "AI티"의 정체라는 판단):
- **아이콘은 액션에, 그리고 정보 블록의 인덱스에만.** 아이콘이 붙는 곳은 길찾기·공유·찜·＋·×·사이드 체크, 그리고 정보 블록의 **핀·시계 열**뿐이다. 정보 블록은 예외로 두는데(2026-09-03) 거기서 아이콘은 장식이 아니라 **행의 종류를 가리키는 인덱스**이고, 접힌 주소가 핀 아래로 들여쓰기되게 하는 정렬 기준이다. 값 앞에 체크·별 같은 장식 아이콘을 다는 것은 여전히 금지다.
- **행 리스트 대신 정보 블록.** 관련된 값은 붙이고 그룹 사이만 벌린다. 같은 생김새의 행이 세 번 반복되면 화면이 표처럼 읽힌다.
- **위계는 회색 계층으로.** fg(값) → fg-secondary(보조) → fg-tertiary(메타). 섹션 안을 보더로 나누지 않는다(메뉴·리뷰 행 사이 헤어라인만 예외 — 값이 두 열이거나 항목이 여러 줄이라 구분선이 필요하다).
- **섹션 제목에도 위계.** "대표 메뉴"·"여기 다녀오셨나요?"·"리뷰"는 16 semibold, "사이드"는 칩이 곧 내용이라 12 회색 라벨로 낮춘다.
- **여백 리듬은 불균등하게.** 사진 아래 12 / 상호 블록 아래 20 / 공지 행 아래 16 / 정보 블록 아래 16 / 버튼 줄 아래 16. 블록 **안**은 더 촘촘하게 — 역 줄↔펼친 도로명 2, 도로명↔지번 2, 위치↔영업시간 12. 간격이 곧 묶음이라 같은 필드(2) → 다른 필드(12) → 블록 경계(16) 순으로 벌린다. 위치↔영업시간이 6이면 지번과의 2와 구분이 안 돼 영업시간이 주소 셋째 줄로 읽힌다.
- **빈 상태는 한 줄 + 인라인 액션.** "아직 ~가 없어요 / 첫 ~가 되어보세요" 2연타와 일러스트는 쓰지 않는다.
- **숫자만 살린다.** 가격·별점은 semibold + tabular, 단위·날짜·메타는 fg-tertiary로 후퇴. 확인 횟수는 메타 캡션 안이라 tabular만 주고 굵기는 올리지 않는다.

요약 상태에서는 사진 유무와 무관하게 **2번 상호 블록의 확인 캡션("3일 전 확인")까지** 보이는 것이 수용 기준이다(헤더 44 + 사진 144 + 상호 블록 = 257px, 하한 270px에 여유 13px — 뷰포트 높이와 무관하게 고정. 사진 유무로 행이 안 바뀌므로 무사진도 같은 13px, 390×844 실측). 그 아래(정보 블록·버튼 줄)는 본문 스크롤이나 전체 펼침으로 본다. 아래 순서는 전체 펼침 기준.

위에서 아래로 (spec 4.2 순서 엄수):
1. **사진** — 좌우 20 여백의 **가로 스크롤 스트립**(176×128 가로형, 라운드 12, 간격 8, object-cover). 정사각 112로는 접시가 잘려 음식이 안 보였다. 마지막 칸은 항상 가라앉은 배경(bg-sunken)의 **＋ 타일**이라 사진이 있어도 옆에 계속 더 올린다. **사진을 탭하면 전체 화면 뷰어**(변형 (e)). **한 가게 10장까지** — 다 차면 ＋ 타일 자리에 같은 크기의 안내 타일 "10장까지 올릴 수 있어요"(12 회색, 버튼 아님)가 들어가 행 높이와 스크롤 길이가 유지된다. 스크롤바는 감추고 `touch-action: pan-x` + `[data-pan-x]`로 가로 스와이프가 시트 드래그로 새지 않게 한다. **사진이 하나도 없으면** 스트립 대신 **전폭 빈 상태 블록** 하나(높이 128이라 행 높이 144는 그대로, 라운드 12, **채움 없이 옅은 브랜드 헤어라인**(line-brand) 1px): 안에 ＋(24 brand-fg) / "아직 사진이 없어요"(14 medium) / "첫 새우를 올려주세요"(12 fg-tertiary)를 세로 가운데로 쌓고 **블록 전체가** 사진 올리기 표적이다(아이콘 아래 8, 두 줄 사이 2 — 상태와 요청은 한 덩어리). 176 타일 하나만 두면 오른쪽에 담기지 않은 흰 공간이 남아 미완성으로 읽힌다. **카피는 컨테이너가 정한다** — 스트립 안 ＋ 타일은 액션 라벨 "사진 추가", 빈 상태 블록은 상태 한 줄 + 요청 한 줄(decisions 2026-09-03 최종). 블록 안에 다른 링크를 겹쳐 두지 않는다. 회색 채움(bg-sunken)은 쓰지 않는다 — 94%가 무사진이라 시트 맨 위가 늘 회색 상자가 된다. 채운 틴트도 아니다: 채운 틴트는 신규 핀 공지 행의 무게라 빈자리가 공지보다 세지면 안 된다. 점선 박스·큰 카메라 아이콘·그라데이션도 그대로 쓰지 않는다. "네이버에서 사진 보기 ↗"(12 회색, 새 탭 외부 링크)는 **사진 유무와 무관하게 8번 리뷰 끝 한 자리**다 — 빈 상태 옆에 두면 블록과 표적이 겹치고 320에서 두 줄로 접힌다.
2. **상호 블록** — 세 줄: "나라수산"(20 semibold) / "새우구이 · 생새우회 · 마포구"(14 fg-secondary, 색점 없음) / "어제 확인 · 확인 4회"(12 fg-tertiary, 횟수만 tabular). 신선도는 여기서 조용히 말하고, 확인 **액션**은 아래 기여 블록이 갖는다. 닫기 ×는 시트 헤더에 있다.
   (a) 신규 핀이면 이 아래에 공지 행.
3. **정보 블록** — **위치 그룹**과 **영업시간 그룹** 두 덩어리(행 사이 보더 없음). 그룹마다 앞에 **16px 아이콘 열**(핀 `ci--location` / 시계 `ci--clock`, fg-tertiary, 아이콘↔값 6, 14px 행 높이 안에서 광학 정렬 `mt-0.5`)이 서고 값은 그 오른쪽 컬럼에 쌓인다 — 아이콘은 행의 종류를 가리키는 인덱스이자 접힌 주소의 정렬 기준이다. **위치 그룹의 첫 줄은 가장 가까운 지하철역이고, 그 줄이 곧 주소 드롭다운의 헤더다**: 노선색 배지(**16px** 원, 흰 숫자 12/600, 배지끼리·배지↔역명 6) + "가락시장역 2-1번출구에서 90m"(14 fg, 거리 tabular) + 오른쪽 chevron ⌄(16 fg-placeholder, 펼치면 180° 회전). 배지가 20px이면 행 높이(19.6)를 꽉 채워 탭할 수 있는 것처럼 보인다. **주소는 기본이 접힘**이고 이 줄을 누르면 **2 아래로** 도로명 "서울 마포구 마포대로12길 34"(14 **fg-secondary** — 역 줄이 첫 값이라 한 단계 낮췄다) / 지번 "마포동 123-4"(12 fg-tertiary) + 오른쪽 작은 아웃라인 [복사](28px, 라운드 8)가 열린다 — 주소는 길찾기·복사할 때만 필요한 값이라 상시 두 줄을 먹을 이유가 없다. 복사하면 토스트 "주소를 복사했어요". **지번은 시·구 접두어를 떼고 동·번지만** 남긴다("서울 송파구 가락동 600" → "가락동 600") — 도로명 바로 아래 줄이라 접두어가 두 번 읽힌다. 뒤에 붙은 건물명·층은 크롤링 잔재라 같이 자르고, 형식을 못 읽으면 원문을 그대로 둔다. 환승역은 **숫자 호선 전부** 나란히(서울 최대 3개), 수인·분당선처럼 숫자가 없는 노선은 원 안에 넣을 숫자가 없어 **배지 없이 역명만**. **거리는 역 중심이 아니라 가장 가까운 출구까지**(중앙값 53m 짧다) 재고, 직선거리라 10m 반올림한다 — 화면 1 카드와 같은 표기다. 한 줄이 320에서 넘치면 출구를 떼고 "가산디지털단지역에서 140m"로 줄인다(핀·chevron이 44px을 먹은 뒤로 현재 데이터 2곳). **역이 800m 밖이면(경기·서울 외곽) 역 줄도 chevron도 없고 주소가 그냥 보인다** — 헤더와 본문이 같은 disclosure는 만들지 않는다. **배지는 aria-hidden이고 호선은 헤더 버튼의 `aria-label`이 문장으로 읽어 준다**("3호선 8호선 가락시장역 2-1번출구에서 90m") — 9호선 #A49D87 위 흰 숫자는 대비 2.4:1이라 색은 보조 신호여야 한다. 그 아래 **12 띄우고** 시계 열 + 영업시간 메모 "23:00 라스트오더, 월 휴무"(14 fg-secondary) + 오른쪽 옅은 [수정](12 fg-tertiary 텍스트 버튼). 초록 "영업 중" 판정은 없다(데이터가 자유 메모). **영업시간이 없으면** 그 줄이 입력 입구가 된다: "영업시간을 알려주세요"(14 fg-secondary) + chevron ›, 이때는 **시계 아이콘까지 한 표적**이다(옆을 눌러도 안 열리면 이상하다).
4. **버튼 줄** — 48px 3개, 라운드 12, 간격 8: **[길찾기](브랜드 레드 채움, 흰 글자, 폭 2)** [공유](아웃라인, 폭 1) [♡ 찜](아웃라인, 폭 1). 찜을 켜면 하트 채움 + 레드 틴트(red-10 배경, red-600 보더·글자). 길찾기는 네이버 지도 앱 딥링크(앱 없으면 웹 길찾기), 공유는 기기 공유 시트(없으면 링크 복사 + 토스트 "링크를 복사했어요").
   ─ 8px 띠 ─
5. **대표 메뉴** — 제목 "대표 메뉴"(16 semibold) + 오른쪽 옅은 [수정]. 행: 메뉴명(14) + 단위 "1kg"(12 회색 텍스트, 칩 아님) 왼쪽 / 가격 "60,000원"(14 semibold, tabular) 오른쪽, 행 사이 헤어라인. 가격 없으면 "가격 미확인"(12 회색). 메뉴가 없으면 [수정] 없이 "메뉴 정보가 없어요"(14 회색) + [메뉴 알려주기] 작은 아웃라인.
6. **사이드** — 라벨 "사이드"(12 fg-tertiary) + 오른쪽 옅은 [수정], 아래 pill 3개 고정 순서 [머리버터구이] [라면] [볶음밥]. **있음** = 흰 아웃라인 pill + 체크 아이콘 + 잉크 글자, **없음** = 가라앉은 배경(bg-sunken) 회색 글자(fg-placeholder), 보더·아이콘 없음. 필터 칩이 아니라 사실 표시라 레드 틴트는 쓰지 않는다. 메뉴와 같은 카드 안이라 사이 경계선은 없다.
   ─ 8px 띠 ─
7. **기여 블록** — "여기 다녀오셨나요?"(16 semibold) / "어제 확인됐어요"(12 회색). 아래 아웃라인 버튼 2개 반씩(44px): **[✓ 다녀왔어요]** [리뷰 남기기]. 다녀왔어요를 누르면 위 상호 블록의 캡션이 즉시 "오늘 확인 · 확인 5회"로 바뀌고 버튼은 틴트 [✓ 확인했어요](red-10 배경, red-600 글자, 더 못 누름)로 — 저장에 실패하면 원래대로 돌아가고 토스트 "확인을 저장하지 못했어요". 취소 없음, 핀당 하루 1회. 확인 줄을 정보 행에서 떼어내 액션만 모은 자리라, 정보 블록에는 버튼이 [복사]밖에 없다.
   ─ 8px 띠 ─
8. **리뷰** — 제목 행: "리뷰" + 개수 "2"(16 회색). **리뷰 3개 이상일 때만** 오른쪽에 "★ 4.7"(잉크 별 + 14 semibold). 리뷰 행: 닉네임(14 semibold) + 날짜 "2026.08.27"(12 회색, tabular) 오른쪽 / 별 5개(12px, 채운 별 잉크·빈 별 gray-200) / 후기(14) / 사진 있으면 64px 라운드 12 썸네일. 행 사이 헤어라인. **빈 상태는 "아직 리뷰가 없어요" 한 줄뿐** — [리뷰 남기기]는 바로 위 기여 블록이 이미 갖고 있어 같은 화면에 두 번 두지 않는다. 사진 있는 가게는 섹션 끝에 "네이버에서 사진 보기 ↗".

9. **맨 아래 한 줄** — 12 회색 텍스트 버튼 3개, 세로 헤어라인으로 구분: "정보 수정 제안 │ 신고 │ 사장님이신가요?". 아래 safe-area 여백.

**수정 입구는 두 문법으로만 나타난다**(spec 4.2 "수정 입구는 필드마다" 유지): 값이 **없으면** 그 필드 자리가 눈에 띄는 인라인 입구가 되고(첫 사진·영업시간을 알려주세요·메뉴 알려주기), 값이 **있으면** 섹션 오른쪽에 옅은 [수정](12 fg-tertiary)이 붙는다(영업시간·대표 메뉴·사이드). 사진은 스트립 끝의 ＋ 타일이 곧 입구다. 하단 "정보 수정 제안"은 어디에도 안 걸리는 것들의 안전망.

**아직 없는 플로우의 입구**(첫 사진 올리기·영업시간·대표 메뉴·사이드 수정·메뉴 알려주기·리뷰 남기기·정보 수정 제안·가게 신고·사장님이신가요?)는 자리·스타일만 확정하고 누르면 토스트 "준비 중이에요"(화면 1 [제보]와 같은 톤. 제보 Phase 3, 리뷰 Phase 4, 관리 Phase 6에서 연결). **예외는 사진 신고 하나** — 뷰어 안에서 사유 선택까지 실제로 동작한다(변형 (e)). 익명 업로드 이미지는 "준비 중이에요"로 미뤄 둘 수 있는 종류가 아니다. 전부 캡션 급이거나 빈 행일 때만 나타나 주 액션(길찾기·다녀왔어요)과 경쟁하지 않는다.

- (b) 사진 여러 장 — 1번이 실제 사진 3장 + ＋ 타일(빈 상태 블록 없음). 10장이 다 찬 가게는 ＋ 타일 대신 안내 타일.

- (d) 상태 — 로딩: 상호·카테고리·확인 캡션 / 정보 블록 / 버튼 줄 자리 스켈레톤(사진은 있을지 알 수 없으니 자리 없음). 정보 블록 자리는 **아이콘 열(16 원) + 값 한 줄씩 두 개**(역·영업시간)다 — **주소 자리는 두지 않는다**: 기본이 접힘이라 실제 화면도 두 줄이다. 에러: 가게 자체는 목록에서 이미 있으므로 추가 로드(리뷰)만 실패할 수 있다 → 8번 자리에 "리뷰를 불러오지 못했어요" + [다시 시도](공용 ErrorState). 없음(잘못된 링크): "가게를 찾을 수 없어요" + [지도로 돌아가기]. 빈 상태는 섹션별(1·3·5·8)로 위에 정의.
- (e) **사진 뷰어(전체 화면)** — 스트립 사진을 탭하면 열린다. 시트·드롭다운·토스트 위에 얹히는 별도 표면이라 브라우저 top layer(네이티브 `<dialog>` + `showModal()`)를 쓴다. 배경 bg-immersive, 글자 fg-on-immersive.
  - 상단(safe-area, 좌우 12): 왼쪽 닫기 ✕(44px 원), 오른쪽 카운터 "2 / 7"(32px 알약, 12 medium tabular). **컨트롤은 전부 bg-immersive-raised 위에 얹는다** — 흰 접시 사진이 뒤에 오면 맨 흰 아이콘·글자는 그대로 사라진다.
  - 가운데: 한 장이 화면에 꽉 차게 `object-contain` — 스트립은 crop(cover), 뷰어는 원본 비율이다. 좌우 스와이프로 넘긴다(CSS scroll-snap, 한 장 = 한 화면). 로딩 중에는 빈 어두운 자리, 실패하면 그 장에 "사진을 불러오지 못했어요"(14).
  - 하단(safe-area + 12, 좌우 20): 왼쪽 "2026.09.03"(14 medium tabular) + " 등록"(14 regular, fg-on-immersive-secondary) — 날짜만 떠 있으면 무슨 날짜인지 알 수 없다. 오른쪽 [⚑ 신고](44px 알약, bg-immersive-raised, 아이콘 16 + 14 medium). 좋아요·공유 같은 다른 액션은 두지 않는다 — 이 화면의 목적은 크게 보는 것과 잘못된 사진을 걸러내는 것 둘뿐이다.
  - 안드로이드 뒤로가기 1회 = 뷰어만 닫히고 시트는 있던 자리·스크롤 그대로. Escape·닫기 ✕도 같다.
  - **신고 시트** — [신고]를 누르면 뷰어 하단에서 사유 패널이 올라온다: 전체 폭 44px 행 4개 [부적절한 사진] [다른 가게 사진] [광고·도배] [기타], 행 사이 헤어라인. **탭이 곧 제출**이라 확인 버튼이 없다(고르고도 안 낸 상태를 만들지 않는다). 접수 중에는 누른 행이 "접수 중…"으로 비활성. 성공하면 뷰어가 닫히며 토스트 "신고를 접수했어요", 실패하면 **뷰어 안에** 토스트 "신고를 접수하지 못했어요"가 뜨고 패널은 그대로다(다시 탭이 재시도 — 뷰어를 닫아 버리면 무엇이 실패했는지 사라진다).


## [화면 3] 제보 플로우 (4단계 + 완료, 프레임 5장) (v1 초안 — 착수 시 v2로 재작성)

위 공통 블록에 이어서:

바텀시트 안에서 진행되는 제보 플로우. 상단에 단계 표시(1/4 형태의 얇은 진행바), 뒤로가기 화살표.

**프레임 1 — 가게 찾기**: 큰 검색창 "가게 이름을 검색해주세요" + 자동완성 리스트에 우리 DB 매치 2개("수성2호왕새우소금구이 · 관악구 · 이미 새우맵에 있어요" 라벨) + 맨 아래 "찾는 가게가 없나요? → 새로 등록하기" 버튼.

**프레임 2 — 위치**: 지도(현 위치 중심)에 드래그 가능한 핀 1개, 하단 "핀을 가게 위치로 옮겨주세요" + 주소 검색 입력 보조 + [여기가 맞아요] 버튼(액센트 레드). 위쪽에 작은 경고 카드 변형: "150m 안에 비슷한 가게가 있어요 — 청춘조개포차 신촌점 [이 가게예요] [다른 가게예요]".

**프레임 3 — 메뉴와 가격**: 입력 줄 — 메뉴명 "왕새우소금구이", 가격 "45,000", 단위 칩 선택([1kg] [500g] [한판] 활성 [반판] [기타]). 아래 토글 "새우회도 팔아요" 꺼진 상태. [다음] 버튼.

**프레임 4 — 선택 항목**: 사진 추가 박스(점선), 사이드 체크 3개, 영업시간 메모 입력 "예: 새벽 2시까지, 월 휴무". 제일 큰 버튼이 [건너뛰고 등록](잉크색), 그 위에 작게 [입력하고 등록].

**프레임 5 — 완료**: 체크 애니메이션 자리, "등록됐어요! 지도에 바로 보여요", "7일간 '새로 제보됨' 표시가 붙어요" 설명, [내 핀 보러가기] 주 버튼 + [카카오톡으로 공유] 아웃라인 + "리뷰도 남겨볼래요?" 링크.

## [화면 6] 데스크탑 — 지도 메인 (좌측 패널 + 지도) (v1 초안 — 착수 시 v2로 재작성)

## [화면 7] 데스크탑 — 상세 (패널 전환) (v1 초안 — 착수 시 v2로 재작성)

위 공통 블록에 이어서 (1440×900):

[화면 6]에서 카드를 클릭한 상태. 왼쪽 패널이 상세로 전환되고, 지도는 해당 마커가 선택 상태(크게 + 살짝 어두운 링).

- 이하 [화면 2]의 1~9 순서 그대로, 400px 폭에 맞게:
  - 사진 빈 상태 박스는 패널 폭 꽉, 높이 160px 정도. 사진 있으면 2열 그리드 썸네일.
  - 정보 블록은 화면 2와 같이 아이콘 열 2개(핀·시계) + 값. **주소는 400px에서도 접힘이 기본**이고 역 줄을 눌러 펼친다 — 폭이 남는다고 상시 노출로 바꾸지 않는다(같은 화면이 뷰포트마다 다른 정보량을 갖지 않게). 역 줄도 400px에서 같은 형태(출구 생략 판정은 320 기준 하나로 통일). 확인 액션은 화면 2와 같이 기여 블록으로.
  - 버튼 줄 [길찾기][공유][찜]은 3등분.
  - 메뉴 리스트·사이드·리뷰 빈 상태·하단 링크 줄까지 전부 포함. 패널 내부 스크롤.
- [길찾기]가 이 화면의 유일한 채운 레드(화면 2와 동일).
- 지도 쪽: 선택 마커 옆에 작은 카드 팝오버는 그리지 않기(패널이 상세니까 중복). 선택 마커 강조만.

변형 요청: 신규 핀 버전 — 상호 아래 옅은 배너 "새로 제보된 곳이에요 · 다녀오셨다면 확인해주세요".
