## [공통 블록] — 모든 프롬프트 맨 앞에 붙임

모바일 웹 서비스 "새우맵" 화면을 디자인해줘. 390×844 모바일 프레임, 라이트 모드.
(844는 **기기** 크기다. 브라우저 주소창·툴바를 빼면 **웹이 실제로 쓰는 높이는 656~702px** — 아래 "세로 예산"을 지켜야 실기기에서 안 눌린다.)

**서비스**: 서울 새우구이 가게 지도. 야장맵·거지맵 같은 사용자 참여형 지도. 크롤링한 421곳으로 시작하고, 사용자가 "다녀왔어요" 확인·리뷰·제보로 갱신한다.

**무드**: 캐치테이블·테이블링 계열의 담백한 정보형. 2026년 한국 앱 트렌드. AI가 만든 티가 나면 실패다.

**스타일 규칙** (2026-09-02 리디자인 — 버틸까 디자인 언어. 토큰 표는 아래)
- 바탕: 화이트/쿨 뉴트럴 그레이(#191F28 계열 램프). 텍스트는 잉크(gray-900).
- 브랜드 새우 레드 #F04A28 — **채운 레드 버튼은 화면당 딱 한 곳**([+ 제보] 같은 주 액션). 활성 칩·라벨은 레드 **틴트**(연한 배경 red-10 + red-600 보더·글자), 클러스터 마커는 레드 원. 그 외 남발 금지.
- 카테고리 색: 새우구이(구이) = 코랄 #F0885C, 생새우회(회) = 틸 #14957B. **마커 링에만**(카드 썸네일 자리의 색점은 2026-09-07 새우 플레이스홀더로 대체됐다 — 카테고리는 링이 말한다). 배경 칠하기 금지. 화면 라벨은 "새우구이"·"생새우회".
- 폰트: Pretendard Variable, 자간 -2%, 행간 140%. 텍스트 스타일 12종(Title/Body/Caption × 굵기)만 쓴다. 가격·거리·단위 숫자는 tabular numbers. 절대 날짜는 연도까지 쓴다("2026.08.27") — 연도 없는 "8.27"은 몇 년 전 사진인지 알 수 없어 폐기했다. 상대 시간("어제 확인")은 신선도에만.
- 라운드: 6(미니칩) / 8(입력·컨트롤) / 12(카드·트랙·토스트) / 20(시트 상단) / pill(칩·FAB). 임의 라운드 금지.
- **별점의 마크는 별이 아니라 새우다**(2026-09-07). `shrimp.webp`의 알파를 마스크로 써 `currentColor`로 칠하므로 채움·빔이 별과 같은 문법(색 하나)으로 갈린다. 색은 **브랜드 레드**(채움 `brand-fg` = red-600, 빔 gray-200) — 빔과의 대비가 잉크·코랄보다 좋고 브랜드가 산다. 코랄은 카테고리 색(새우구이)이라 의미가 겹쳐서 쓰지 않는다. "채운 레드는 화면당 한 곳"은 **버튼** 규칙이라 여기 걸리지 않는다(클러스터 레드 원과 같은 결). 12·14px에선 빔이 뭉개서 리뷰 행은 **16px**, 평균 옆은 **18px**이다. 접근 이름은 "별점 N점" 그대로다(바뀐 건 UI뿐).
- 보더는 헤어라인(gray-100·200). 그림자는 지도 위에 뜨는 요소와 시트 상단에만 옅게(float/upper/fab/marker/marker-selected 5종).
- 칩: pill 아웃라인 기본, 활성만 레드 틴트. 정렬·탭 전환은 세그먼트(가라앉은 트랙 + 흰 활성 세그먼트).
- 아이콘: 얇은 라인 아이콘(coolicons). 이모지 금지.
- **모바일(<1024)** 지도 위에는 검색 바와 칩 행 **두 층만** 띄운다(둘 다 pill — 불투명 블록 금지). **데스크탑(1024~)은 칩 행 한 층만** 지도 위에 두고 검색 바는 패널 안이다(결과가 나오는 표면에 입력을 붙인다 — decisions 2026-09-08). 어느 그릇이든 로고·카운터·이벤트·주 버튼은 지도 위에 두지 않는다. 마커: 클러스터 = 레드 원 + 가게 수, 개별 핀 = 썸네일 원 + 카테고리색 링(썸네일 없으면 가라앉은 원 안 **새우 26px**).

브라우저 UI가 142~188px을 먼저 가져간다. 남는 높이를 이렇게 나눈다(702 기준):
- **상단 두 층(검색 바 + 칩 행) = 110px.** 둘 다 지도 위에 뜨므로 지도를 지우지는 않지만 그만큼 가린다. 여기에 고정 px 요소를 더할 때마다 **그 값은 통째로 지도에서 빠진다** — 뷰포트가 줄어도 고정값은 안 줄기 때문이다.
- **시트 요약** = 40dvh(목록 281) / max(30dvh, 270)(상세) / max(40dvh, 330)(제보 2단계). **px 하한이 실기기에서 구속력을 갖는다** — 702px에서 제보는 40%(281)가 아니라 330이 걸린다.
- **가려지지 않은 지도 = 110~421의 311px.** 지도의 중심은 화면 정중앙(351)이 아니라 **이 띠의 한가운데(265)**에 맞춘다.

**데스크탑 그릇 (1024px~, v3 2026-09-08 — 화면 6~9)**
- 320~1023은 유동 모바일(위 세로 예산). **1024부터 풀블리드 지도 + 그 위에 떠 있는 왼쪽 패널 420px**(여백 16, 라운드 20, `shadow-panel`. 기준 프레임 1440×900, 확인은 1440×900 · 1280×800 · 1024×768). 새 화면이 아니라 **같은 컴포넌트를 CSS로 다른 자리에 놓는 것**이다 — 데스크탑에만 있는 요소는 브랜드 줄 [＋ 제보]·줌 컨트롤·마커 프리뷰·정렬 세그먼트·목록 끝 CTA다. 폭 420·480은 스페이싱 스케일(`w-105`·`w-120`), 임의값이 아니다.
- 지도 위에 뜨는 것은 **칩 행 한 층뿐**(검색 바는 패널 안 → 패널 안 요소에는 그림자를 주지 않는다). 시트 핸들·FAB 줄 없음. 패널은 접지 않는다(2026-09-08 만들어 본 뒤 뺐다). 채운 레드는 여전히 화면당 한 곳(목록 = **목록 끝 [아는 새우집 제보하기]**, 상세 = [길찾기], 제보 = 단계마다 바닥 CTA 하나 — 화면 3). 상단 [＋ 제보]는 아웃라인이다.
- **패널이 지도를 덮으므로 지도 이동은 왼쪽으로 (패널 폭 + 여백)만큼 보정한다** — 안 하면 선택한 마커가 패널 뒤로 숨는다(`lib/layout.ts` PANEL_* 상수 = CSS와 같은 값).
- 패널 전환(상세·제보·내 활동)은 모바일 시트 모드와 1:1. **지도가 필요 없는 오버레이**(로그인·리뷰 폼·사유·사진 신고·탈퇴 확인)만 딤 40% 위 중앙 480 모달(라운드 16 — 이 용도의 토큰). 제보는 2단계가 본 지도에서 핀을 찍으므로 모달이 아니라 패널이다.
- 호버는 마우스에만 반응한다: 카드 hover → 지도의 해당 마커 확대, 마커 hover → **프리뷰**(사진 있으면 사진 카드, 없으면 상호 / 대표 메뉴 두 줄 툴팁). 터치 탭의 에뮬레이션 hover는 무시.

**금지 (AI티)**: 크림+세리프 조합, 카드마다 색 띠, 이모지 섹션 헤더, 전면 라운드, 그라데이션 배경, 보라색. — **예외 하나**: 지하철 노선색은 우리가 고른 색이 아니라 사실 표기라 5호선 보라(#794698)를 그대로 쓴다. 16px 배지 안에서만이고 다른 곳에는 안 번진다(decisions 2026-09-03).

## [화면 1] 지도 메인

위 공통 블록에 이어서:

풀스크린 지도 위에 **두 층만** 얹힌 메인 화면. 지도는 밝은 회색 톤 플레이스홀더(네이버지도 느낌)로 두고 마커만 표시.

위에서 아래로:
1. 검색 바 — 상태바 아래, **지도 위에 떠 있는 흰 pill 하나**(칩과 같은 층·같은 문법: 헤어라인 보더 + 옅은 그림자): 돋보기 + "가게·동네 검색" + **오른쪽 끝 프로필 버튼**(익명 = 사람 아이콘 24 fg-secondary, 로그인 = 28px 레드 틴트 원 + 닉네임 첫 글자 — 내 활동 입구, 화면 5). 검색어가 있으면 그 자리는 지우기 ✕다. 로고·다른 버튼 없음. **불투명 흰 블록으로 지도를 덮지 않는다** — 실기기 뷰포트는 656~702px뿐이라 고정 72px 블록이 보이는 지도를 통째로 먹는다 (decisions 2026-09-04).
2. 칩 행 — 블록 아래 10px, 지도 위에 떠 있는 pill 한 줄: **[전체 ▾] 드롭다운 칩**(누르면 아래에 흰 카드 목록 전체 / 새우구이 / 생새우회, 선택하면 칩이 레드 틴트 "새우구이 ▾") + 토글 pill 4개 [머리버터구이] [라면] [볶음밥] [찜한 곳](흰 아웃라인, 켜면 틴트, AND — 전부 "목록을 좁히는 필터"로 성격이 같다. [새로 들어온 집]은 화면을 바꾸는 입구였어서 뺐다, 2026-09-05). 칩 행 전체가 넘치면 함께 가로 스크롤(드롭다운 칩도 같이 넘어감). 사이드 칩을 켰는데 0곳이면 시트에 "조건에 맞는 집이 없어요 · 칩을 풀거나 지도를 옮겨보세요" + [필터 해제].

## [화면 2] 가게 상세 (바텀시트: 탭=요약, 드래그=전체, 스와이프=닫기)

위 공통 블록에 이어서:

지도 메인에서 카드나 마커를 탭하면 **같은 바텀시트**의 내용이 목록에서 상세로 바뀐다. 처음엔 **요약**(화면 높이의 30%, 최소 270px)으로 열리고, 위로 드래그하거나 핸들을 탭하면 **전체**(92%)로 펼쳐진다. 요약에서 본문을 위로 끌면 그대로 전체로 이어지고(스크롤 체이닝), 전체에서 맨 위를 아래로 끌면 요약으로 돌아온다. 요약에서 아래로 스와이프하면 닫히고 목록으로 돌아간다(목록은 있던 높이·스크롤 그대로). 공유 링크 `/place/[id]`로 들어오면 이 화면이 요약 상태로 열려 있다. 상세가 열린 동안 FAB 줄(현위치·제보)은 숨긴다. 지도는 해당 핀이 시트에 가려지지 않게 가시 영역 중앙으로 옮기고 핀은 선택 상태(확대 + 흰 링 + 진한 그림자).

시트 헤더(44px)는 핸들(50×6) + **오른쪽 닫기 ×**뿐이다. 상호가 아니라 시트 크롬에 있어 사진 유무·스크롤 위치와 무관하게 늘 같은 자리다. 좌우 여백 20·상단 라운드 20은 화면 1과 같다.

**이 화면의 채운 레드는 4번 [길찾기] 한 곳.** 카테고리 색은 쓰지 않는다(상세 안에서는 텍스트 태그). 섹션 사이는 8px 가라앉은 띠(bg-dim). UI 문장을 em dash·가운데 점으로 잇지 않는다(카드처럼 메타를 나열할 때만 가운데 점).

**이 화면의 디자인 규칙**(2026-09-03 리디자인 — 균일한 리듬이 "AI티"의 정체라는 판단):
- **아이콘은 액션에, 그리고 정보 블록의 인덱스에만.** 아이콘이 붙는 곳은 길찾기·공유·찜·＋·×·사이드 체크, 그리고 정보 블록의 **핀·시계 열**뿐이다. 정보 블록은 예외로 두는데(2026-09-03) 거기서 아이콘은 장식이 아니라 **행의 종류를 가리키는 인덱스**이고, 접힌 주소가 핀 아래로 들여쓰기되게 하는 정렬 기준이다. 값 앞에 체크·별 같은 장식 아이콘을 다는 것은 여전히 금지다.
- **행 리스트 대신 정보 블록.** 관련된 값은 붙이고 그룹 사이만 벌린다. 같은 생김새의 행이 세 번 반복되면 화면이 표처럼 읽힌다.
- **위계는 회색 계층으로.** fg(값) → fg-secondary(보조) → fg-tertiary(메타). 섹션 안을 보더로 나누지 않는다(메뉴·리뷰 행 사이 헤어라인만 예외 — 값이 두 열이거나 항목이 여러 줄이라 구분선이 필요하다).
- **섹션 제목에도 위계.** "대표 메뉴"·"여기 다녀오셨나요?"·"리뷰"는 16 semibold, "사이드"는 칩이 곧 내용이라 12 회색 라벨로 낮춘다.
- **여백 리듬은 불균등하게.** 사진 아래 12 / 상호 블록 아래 20 / 공지 행 아래 16 / 정보 블록 아래 16 / 버튼 줄 아래 16. 블록 **안**은 더 촘촘하게 — 역 줄↔펼친 도로명 2, 도로명↔지번 2, 위치↔영업시간 12. 간격이 곧 묶음이라 같은 필드(2) → 다른 필드(12) → 블록 경계(16) 순으로 벌린다. 위치↔영업시간이 6이면 지번과의 2와 구분이 안 돼 영업시간이 주소 셋째 줄로 읽힌다.
- **빈 상태는 한 줄 + 인라인 액션.** "아직 ~가 없어요 / 첫 ~가 되어보세요" 2연타와 일러스트는 쓰지 않는다.
- **숫자만 살린다.** 가격·별점은 semibold + tabular, 단위·날짜·메타는 fg-tertiary로 후퇴. 확인 횟수는 메타 캡션 안이라 tabular만 주고 굵기는 올리지 않는다.

요약 상태에서는 사진 유무와 무관하게 **2번 상호 블록의 확인 캡션("3일 전 확인")까지** 보이는 것이 수용 기준이다(헤더 44 + 사진 144 + 상호 블록 = 257px, 하한 270px에 여유 13px — 뷰포트 높이와 무관하게 고정. 사진 유무로 행이 안 바뀌므로 무사진도 같은 13px, 390×844 실측). 그 아래(정보 블록·버튼 줄)는 본문 스크롤이나 전체 펼침으로 본다. 아래 순서는 전체 펼침 기준.

위에서 아래로 (spec 4.2 순서 엄수):
1. **사진** — 좌우 20 여백의 **가로 스크롤 스트립**(176×128 가로형, 라운드 12, 간격 8, object-cover). 정사각 112로는 접시가 잘려 음식이 안 보였다. 마지막 칸은 항상 가라앉은 배경(bg-sunken)의 **＋ 타일**이라 사진이 있어도 옆에 계속 더 올린다. **사진을 탭하면 전체 화면 뷰어**(변형 (e)). **한 가게 10장까지** — 다 차면 ＋ 타일 자리에 같은 크기의 안내 타일 "10장까지 올릴 수 있어요"(12 회색, 버튼 아님)가 들어가 행 높이와 스크롤 길이가 유지된다. 스크롤바는 감추고 `touch-action: pan-x` + `[data-pan-x]`로 가로 스와이프가 시트 드래그로 새지 않게 한다. **사진이 하나도 없으면** 스트립 대신 **전폭 빈 상태 블록** 하나(높이 128이라 행 높이 144는 그대로, 라운드 12, **채움 없이 옅은 브랜드 헤어라인**(line-brand) 1px): 안에 ＋(24 brand-fg) / "아직 사진이 없어요"(14 medium) / "첫 새우를 올려주세요"(12 fg-tertiary)를 세로 가운데로 쌓고 **블록 전체가** 사진 올리기 표적이다(아이콘 아래 8, 두 줄 사이 2 — 상태와 요청은 한 덩어리). 176 타일 하나만 두면 오른쪽에 담기지 않은 흰 공간이 남아 미완성으로 읽힌다. **카피는 컨테이너가 정한다** — 스트립 안 ＋ 타일은 액션 라벨 "사진 추가", 빈 상태 블록은 상태 한 줄 + 요청 한 줄(decisions 2026-09-03 최종). 블록 안에 다른 링크를 겹쳐 두지 않는다. 회색 채움(bg-sunken)은 쓰지 않는다 — 94%가 무사진이라 시트 맨 위가 늘 회색 상자가 된다. 채운 틴트도 아니다: 채운 틴트는 신규 핀 공지 행의 무게라 빈자리가 공지보다 세지면 안 된다. 점선 박스·큰 카메라 아이콘·그라데이션도 그대로 쓰지 않는다. "네이버에서 사진 보기 ↗"(12 회색, 새 탭 외부 링크)는 **사진 유무와 무관하게 8번 리뷰 끝 한 자리**다 — 빈 상태 옆에 두면 블록과 표적이 겹치고 320에서 두 줄로 접힌다.

## [화면 3] 제보 플로우 (4단계 + 완료, 프레임 5장)

위 공통 블록에 이어서:

지도 메인의 [＋ 제보] FAB(또는 빈 목록의 [제보])를 누르면 **같은 바텀시트**가 목록에서 제보 패널로 바뀐다. 시트 크롬은 화면 2와 같다(헤더 44 = 핸들 + 오른쪽 ✕, 라운드 20, 좌우 20). 스냅은 요약·전체 둘이고 1·3·4단계와 완료는 **전체**로, 2단계만 **요약**으로 내려가 지도와 핀을 보여준다. 이 요약은 상세(30%, 최소 270)보다 높은 **40%, 최소 330px** — ‹ 줄·제목·캡션·주소 입력·CTA가 스크롤 없이 들어가야 하고, 실기기 702px에서는 40%(281)가 아니라 **330px 하한이 걸려** 지도가 372px 남는다(390×844 기준 500px은 DevTools 값이라 폐기 — decisions 2026-09-04). 상세와 달리 **아래로 스와이프해도 닫히지 않는다**(요약에 머문다) — 입력 중인 값이 손가락 한 번에 사라지면 안 된다. 그만두는 길은 헤더 ✕(제보 그만두기, 확인 없음)와 1단계에서의 뒤로가기뿐이다. 제보가 열린 동안 FAB 줄과 지도 위 두 층(검색 바·칩 행)을 숨긴다 — 지도는 핀을 맞추는 용도뿐이고, 우리 DB 검색과 주소 검색이 한 화면에 같이 보이면 안 된다. 기존 마커는 그대로 보이고, 2단계에서 탭하면 그 가게로 중복 의심 패널이 열린다(변형 (a)). 다른 단계에선 눌러도 반응하지 않는다.

**뒤로가기는 단계 하나.** 플로우 전체가 브라우저 히스토리 엔트리 하나라 뒤로가기(또는 패널의 ‹)는 이전 단계로 돌아가고, 1단계에서 한 번 더 누르면 플로우가 닫힌다. URL은 `/` 그대로다. 완료 뒤 [내 핀 보러가기]나 1·2단계에서 기존 가게로 넘어가면 상세 `/place/[id]`가 이 엔트리를 **대체**해 뒤로가기 한 번에 목록이다.

**이 화면의 채운 레드는 단계마다 하단 CTA 하나.** 단계가 곧 화면이라 [새로 등록하기] → [여기가 맞아요] → [다음] → [건너뛰고 등록]/[등록하기] → [내 핀 보러가기]가 각 화면의 유일한 채운 레드다(FAB 줄은 숨어 있다). 중복 의심 패널의 [이 가게예요] [다른 가게예요]는 둘 다 아웃라인 — 정답을 우리가 모르는 질문에 색으로 답을 유도하지 않는다. 카테고리 색은 쓰지 않는다.

**이 화면의 디자인 규칙**(화면 2의 규칙을 그대로 잇는다):
- **퍼널 문법.** 단계마다 제목(24 bold) + 낮춘 캡션(14 fg-secondary) → 입력 → 시트 바닥에 고정된 CTA(48, 전폭, 라운드 12, 위 12·아래 safe-area). 본문만 스크롤된다. 헤더 아래 **4칸 세그먼트 진행바**(높이 2, 칸 사이 4, 지난 칸 brand·남은 칸 line-hairline). "1/4" 숫자는 없다 — 칸이 곧 숫자다.
- **‹는 패널 첫 줄에.** 44px 히트의 `ci--chevron-left`가 진행바 아래 한 줄을 차지하고 제목은 그 아래에서 시작한다(토스 퍼널의 앱바 자리). 헤더는 시트 드래그 표적이라 버튼을 헤더 안에 더 두지 않는다.
- **아이콘은 액션에만.** ‹, ✕, 돋보기, ＋ 타일, 사진 제거 ✕, 공유. 정보 앞 장식 아이콘·체크 애니메이션은 없다.
- **입력은 한 종류.** 48px, 라운드 8, 가라앉은 배경(bg-sunken), 보더 없음 — 화면 1 검색바와 같은 톤. 라벨은 입력 위 12 fg-secondary(입력↔라벨 6), 오류는 입력 아래 12 brand-fg 한 줄. placeholder는 예시 한 개("예: 왕새우 소금구이").
- **위계는 회색 계층.** 매치·주소 행은 상호/도로명(16 semibold 또는 14 medium, fg) 위에 메타(12 fg-tertiary) 한 줄. 강조는 숫자만(거리 "40m"·가격 tabular).
- **여백 리듬.** 제목↔캡션 4, 캡션↔첫 입력 20, 필드 사이 12, 그룹 사이 28, 마지막 입력↔CTA 24.
- **빈 상태는 액션 하나.** 설명 캡션 없이 CTA만 — 라벨이 이미 무엇을 하는지 말한다. 일러스트·2연타 카피·안내 한 줄 없음 (decisions 2026-09-04).
- UI 문장을 em dash·가운데 점으로 잇지 않는다(메타 나열만 가운데 점).

위에서 아래로 (spec 4.3 순서 엄수):
1. **가게 찾기**(전체) — 진행바 ▮▯▯▯. 제목 "가게 이름을 검색해주세요" / 캡션 "이미 있는 가게면 바로 알려드려요". 입력(돋보기 16 fg-tertiary 왼쪽, placeholder "예: 나라수산")은 패널이 열리면 바로 포커스. 두 글자부터 우리 DB를 상호로 맞춰(공백·기호 무시) **최대 5행**, 닮은 순: 상호(16 semibold) / "마포구 · 새우구이"(12 fg-tertiary) 왼쪽, 오른쪽 틴트 미니칩 **"이미 있어요"**(xs). 행 높이 56, 행 사이 헤어라인, 행 전체가 버튼이고 누르면 그 가게 상세로 넘어간다(플로우는 닫힌다). 매치가 없으면 목록 자리 없이 바로 캡션. CTA **[새로 등록하기]**는 **매치 유무와 무관하게 늘** 있다(매치가 있어도 "그중엔 없다"며 등록할 수 있어야 한다). 그 위 설명 캡션은 두지 않는다 (decisions 2026-09-04). 이름 없이 누르면 입력 아래 "가게 이름을 입력해주세요"(40자 상한).
2. **위치**(요약) — 진행바 ▮▮▯▯. 시트가 요약으로 내려가고 지도에 **제보 핀** 하나(레드 머리 28 + 흰 점, 줄기 14, 앵커는 바닥 중앙, 44px 히트)가 현 위치에 선다(위치를 허용하지 않았으면 보던 지도 중심, 그것도 없으면 서울 중심). 지도는 줌 17로 가고 핀이 시트 위 가시 영역 가운데 오게 옮긴다. **지도를 탭하면 핀이 그 자리로 온다**(지도는 움직이지 않는다) — 손가락으로 핀을 집어 끄는 것보다 "여기" 탭이 쉽다. 드래그는 미세 조정용으로 남는다. 패널: 제목 "핀을 가게 위치로 옮겨주세요" / 캡션 "지도를 탭하거나 핀을 끌어 맞춰주세요" / 주소 검색 입력(돋보기, placeholder "도로명 주소로 찾기") / CTA **[여기가 맞아요]**. 결과 목록이 열리면 본문이 스크롤된다. 전체로 펼치는 건 핸들(탭·드래그)뿐 — 입력 폼이라 본문 드래그 체이닝은 두지 않는다(텍스트 선택·스크롤이 우선).
   - **주소 검색은 핀을 옮기는 보조다.** 엔터(IME 조합 중 제외)로 네이버 지오코더를 한 번 부르고 결과 **최대 5행**을 입력 아래에 편다: 도로명(14 medium) / 지번(12 fg-tertiary), 행 44, 헤어라인. 행을 누르면 핀이 그 좌표로 옮겨가고 목록은 닫힌다. 결과는 목록이 열려 있는 동안만 화면에 있고 **어디에도 저장하지 않는다**(CLAUDE.md 규칙 2). 저장되는 것은 사용자가 확정한 핀 좌표와 그 좌표로 판정한 구뿐이라 도로명·지번 주소는 비어 있다(아래 "저장되는 것").
   - 검색 4상태: 로딩 = 스켈레톤 2행 / 결과 없음 = "검색 결과가 없어요"(14 fg-secondary 한 줄) / 실패 = "주소를 찾지 못했어요" 한 줄(입력을 고쳐 다시 엔터가 재시도) / 정상 = 위 목록.
   - **[여기가 맞아요]**를 누르면 핀 좌표로 시군구를 판정한다(전국 — 서울은 "마포구", 밖은 "김포시(경기)"). 한국 밖(바다)이면 입력 아래 "한국 안의 위치만 제보할 수 있어요"가 뜨고 머문다(변형 (b)). 안이면 150m 안에 상호가 비슷한 가게가 있는지, 없으면 핀 자리 30m 안에 가게(상호 무관)가 있는지 본다(변형 (a)). 둘 다 없으면 3단계.
3. **메뉴와 가격**(전체) — 진행바 ▮▮▮▯. 제목 "메뉴와 가격을 알려주세요" / 캡션 "대표 메뉴 한 줄이면 돼요. 이름·가격·단위를 모두 채워주세요"(3단계는 세 필드가 다 필수라 캡션에서 한 번만 밝힌다 — 필드마다 `*`는 셋 다 필수라 정보량이 0이다, decisions 2026-09-04). **구이 줄**: 라벨 "메뉴명" + 입력(placeholder "예: 왕새우 소금구이", 30자) / 12 아래 라벨 "가격" + 숫자 입력(오른쪽 안에 "원" 14 fg-tertiary, 숫자 키패드) / 12 아래 라벨 "단위" + pill 칩 6개 [1kg] [500g] [한판] [반판] [마리] [단위 없음] — **줄바꿈**(320·390에서 2줄. 가로 스크롤은 마지막 칩을 숨겨 버렸다), 활성만 틴트. [마리]를 고르면 **칩 행 아래에** 폭 128 입력 "몇 마리"(접미 "마리", 숫자 키패드)가 펼쳐지며 바로 포커스된다 — 행 안 오른쪽 끝에 두면 스크롤 밖이라 보이지 않았다. 그 아래 28 띄우고 **스위치 행** "새우회도 팔아요"(16 medium 왼쪽, 오른쪽 스위치 44×24: 트랙 line → brand, 흰 썸). 켜면 12 아래 같은 3필드의 **회 줄**(라벨 "새우회 메뉴명", placeholder "예: 생새우회")이 펼쳐진다. CTA **[다음]** — 메뉴명·가격·단위가 빠지면 해당 입력 아래 "메뉴 이름을 알려주세요" / "가격을 숫자로 알려주세요" / "단위를 골라주세요". 大中小·인분은 크롤 데이터에만 있는 표기라 칩에 없다(spec 2 가공 규칙 — 제보로 새 표기를 늘리지 않는다).
4. **선택 항목**(전체) — 진행바 ▮▮▮▮. 제목 "더 알려주실 게 있나요?" / 캡션 "모두 선택 사항이에요". **사진**: 라벨 "사진" + 오른쪽 "2/10"(12 fg-tertiary tabular). 88px 타일 행(간격 8, 가로 스크롤): 맨 앞 **＋ 타일**(bg-sunken, ＋ 20 fg-secondary + "사진 추가" 12 — 화면 2 스트립의 ＋ 타일과 같은 문법)을 누르면 기기 사진 선택기(이미지만, 여러 장), 고른 사진은 그 뒤로 라운드 12 미리보기 타일 + 오른쪽 위 제거 ✕(24 원, bg-immersive-raised 위 흰 ✕). 10장이 차면 ＋ 타일이 사라진다. 점선 박스는 쓰지 않는다. **사이드**: 라벨 "사이드" + pill 3개 [머리버터구이] [라면] [볶음밥] — 화면 2 상세와 달리 여기서는 선택 칩이라 활성이 레드 틴트다. **영업시간**: 라벨 "영업시간" + 입력(placeholder "예: 새벽 2시까지, 월 휴무", 80자). CTA는 **하나**: 아무것도 안 넣었으면 **[건너뛰고 등록]**, 하나라도 넣었으면 **[등록하기]**로 라벨이 바뀐다 — 제출 버튼이 둘이고 큰 쪽이 입력을 버리는 v1 구성은 함정이라 폐기(decisions 2026-09-04). 누르면 "등록 중…"(비활성)이고 실패하면 토스트 "등록하지 못했어요. 다시 시도해주세요" + 입력은 그대로(같은 버튼이 재시도).
5. **완료**(전체) — 진행바·‹ 없음. 제목 "등록됐어요!" / 캡션 "지도에 바로 보여요. 7일간 '새로 제보됨' 표시가 붙어요". 20 아래 **요약 카드**(라운드 12, 헤어라인 보더, 안 여백 16): 상호(16 semibold) / "마포구 · 새우구이"(12 fg-tertiary) / 대표 메뉴 "왕새우 소금구이 1kg 35,000원"(14, 가격 tabular), 오른쪽 위 [공유] 아이콘 버튼(44, `ci--share-outline` — 상세 버튼 줄과 같은 아이콘) — 기기 공유 시트, 없으면 링크 복사 + 토스트 "링크를 복사했어요". 카카오톡 전용 버튼은 Phase 5(OG와 함께). CTA **[내 핀 보러가기]** → 새 가게 상세(화면 2 변형 (a)의 신규 핀 공지 행이 보인다). CTA 위 12에 가운데 텍스트 링크 "리뷰도 남겨볼래요?"(14 fg-secondary, 밑줄 없음) — Phase 4까지 토스트 "준비 중이에요". **제목 위 가운데 168px 새우 냄비 아트**가 한 번 튀며 등장하고(`saeu-pop` 520ms 오버슈트 이징, `prefers-reduced-motion` 존중) 제목·캡션도 **이 화면에서만 가운데 정렬**이다 — 제보를 끝낸 순간이 이 앱에서 유일하게 축하할 자리라 여기만 예외를 둔다. 왼쪽 정렬 작은 아이콘으로는 축하가 아니라 그냥 장식이 된다(2026-09-07 실기기 656 확인). 냄비가 구이 쪽 그림인 건 알고 쓴다 — 생새우회 전용 가게 제보에도 같은 아트가 나온다. **체크마크 애니메이션은 여전히 쓰지 않는다** — 클리셰이고 제목이 이미 "등록됐어요!"로 말한다.

**저장되는 것**: 상호, 핀 좌표, 좌표로 판정한 시군구(서울 "마포구", 밖은 "김포시(경기)"), 메뉴 1~2줄(구이 줄 → 새우구이, 회 줄 → 생새우회), 사이드, 영업시간 메모. 도로명·지번은 비어 있고(상세 정보 블록에 "주소를 알려주세요" 입구가 선다 — 화면 2 항목 3의 영업시간 입구와 같은 문법), 최근접역은 서버가 나중에 계산한다(Phase 6). 사진은 목 단계에서 버린다(저장소 Phase 6). 제보 핀은 즉시 노출되고 7일간 "새로 제보됨"이다(spec 5).

## [화면 4] 신규 확인 — 사용자 화면에는 없다 (관리자로, Phase 6)

**결정 2026-09-05: 심판대(신규 목록 + 맞아요/달라요)를 사용자 화면에서 뺐다.** 만들어 눌러 본 뒤 참여가 나오지 않을 것으로 판단했다. 근거는 셋이다.

1. **판단 비용이 다르다.** 거지맵 심판대가 돈 이유는 "이 가격이 맞냐"가 안 가본 사람도 사진만 보고 즉석에서 답할 수 있는 질문이라서다. "이 새우집이 실제로 있냐 / 정보가 맞냐"는 **가서 먹어봐야** 안다. 형식만 따라 하면 빈 목록이 남는다.
2. **모수가 없다.** 서울 400곳에 주 신규 3곳, 그중 이용자가 다녀온 곳이 있을 확률은 사실상 0이다. 초기에는 신규가 0~2곳이라 패널이 늘 비어 있고, 빈 화면으로 가는 입구가 상시로 떠 있게 된다.
3. **운영자가 더 잘한다.** 제보 시 텔레그램 알림 + 24시간 내 플레이스 링크 확인(spec 5)이 크라우드 검증보다 빠르고 정확하다. spec 4.5 관리자 탭 "사후 확인(새 제보)"과 기능이 겹친다.

**대신 남긴 것**
- **신규 표시는 그대로**: 카드의 "새로 제보됨" 틴트 라벨, 지도의 점선 링 마커, 상세의 신규 공지 행(화면 2 변형 (a)). 신규는 *정보*로 보이고 *참여 요구*로는 보이지 않는다.
- **확인 참여는 [다녀왔어요] 하나**(화면 2-7). 실제로 다녀온 사람만 누르는 정직한 장치다.
- **[정보가 달라요]의 사유 시트는 화면 2로 옮겼다** — 상세 맨 아래 [정보 수정 제안]의 입구다(화면 2-9). 이건 참여가 아니라 **오류 신고**라 성격이 다르다: 잘못된 정보를 본 사람은 고치고 싶어 하고, 상세를 보는 중이면 판단할 능력도 있다.
- 칩 행에서 [새로 들어온 집]을 뺐다. 남은 칩 4개는 전부 "목록을 좁히는 필터"로 성격이 같고, 390에서 잘리지 않는다(이전에는 5개 + 드롭다운이라 137px 넘쳐 입구가 화면 밖이었다).

**관리자 화면(Phase 6 /admin "사후 확인" 탭)에서 다시 쓴다.** 그때 필요한 행 구성은 이렇다: 썸네일 + 상호 / "2026.08.27 등록"(연도까지, tabular) / "관악구 · 새우구이" / 대표 메뉴 + 가격 / 상태("검증 전" ↔ 체크 + "확인됨", 확인 1회 이상이면 확인됨) + 액션 [확인] [정보 수정 큐로]. 구현했던 컴포넌트(`new-places-panel.tsx`·`new-place-row.tsx`)와 테스트는 커밋 `cb32d18`에 있다 — 관리자 레이아웃은 시트가 아니라 데스크탑 표라 그대로 붙지 않지만 행 구성과 낙관 확인 로직은 꺼내 쓸 수 있다.
