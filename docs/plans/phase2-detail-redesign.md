# 화면 2(가게 상세) 리디자인

## Context

Phase 2에서 만든 상세 바텀시트가 UI/UX적으로 만족스럽지 않다는 사용자 판단. 구체적 불만 7가지:

1. **요약 상태에서 본문에 닿을 수 없다.** `app/globals.css:347`이 detail·half에서 본문에 `overflow-y: hidden; touch-action: none`을 걸어 어디를 끌어도 시트만 움직인다. `docs/design.md:88` 실측: 사진 있는 가게는 6번 버튼 줄까지 가려면 반드시 한 번 드래그해야 한다. 터치는 그렇다 쳐도 **휠·키보드 사용자는 요약에서 본문에 도달할 경로가 아예 없다(접근성 결함).**
2. 사진이 시트 폭 160px **한 장**뿐. 여러 장 올릴 수 없고, 사진이 있으면 추가할 입구가 없다.
3. 사진 없는 상태(56px 입력 행)가 빈약하다.
4. 닫기 ✕가 상호 행 안에 있어 제목과 경쟁한다.
5. "3일 전 확인 / 확인 4회 + [다녀왔다면]" 줄이 애매하다 — 주소·영업시간과 똑같은 정보 행 생김새인데 안에 액션 pill이 들어 있고, 위아래 헤어라인으로 갇혀 더 도드라진다. "다녀왔다면"은 조건절이라 버튼 문구가 아니다.
6. 수정 입구가 필드마다 다른 문법으로 흩어져 있다.
7. 길찾기가 잉크 채움인데 레드로 원한다.

**목표**: 요약 상태에서 주 액션(길찾기)까지 스크롤 없이 보이고, 사진을 여러 장 다루며, 정보 행과 액션이 섞이지 않는 상세 화면.

**범위 밖 (확인 완료)**: 별도 "메모" 필드는 스펙에 없다 — 문서 전체의 "메모"는 `Place.hoursNote`(영업시간 자유 메모, `decisions.md:108`)뿐이고, 가게에 대한 자유 텍스트는 로그인 필수 리뷰(`spec.md:103-104`, Phase 4)가 담당한다. 새로 만들지 않는다.

## 디자인 언어 — "AI티" 제거 규칙

지금 화면이 AI스러운 원인은 색·라운드가 아니라 **리듬의 균일함**이다. `아이콘 20 + 14 medium + 12 caption + 우측 버튼`이 확인·주소·영업시간 세 행 연속으로 반복되고(`check-line.tsx:19`, `info-rows.tsx:7`·`:26`), 섹션 제목이 전부 16 semibold, 여백이 전부 `px-5 py-3`이다. 국내 트렌드 앱(캐치테이블·테이블링·토스·당근)은 **타이포 위계와 불균등한 여백**으로 구분하고 아이콘은 액션에만 쓴다. CLAUDE.md 지정 참조 순서(버틸까 → 캐치테이블·테이블링)를 그대로 따른다.

| # | 규칙 | 이 화면에서 |
| --- | --- | --- |
| 1 | **아이콘은 액션에만.** 정보 행의 장식 아이콘 금지 | `ci--map-pin`·`ci--clock`·`ci--check` 삭제. 아이콘은 길찾기·공유·찜·`＋`·`✕`·사이드 체크에만 |
| 2 | **행 리스트 대신 정보 블록.** 관련 값은 붙이고 그룹 사이만 벌린다 | 주소·지번·영업시간을 헤어라인 없는 한 블록으로(줄 간격 4/6, 블록 여백 16). 지금의 3연속 균일 행이 사라진다 |
| 3 | **위계는 회색 계층으로.** 보더를 그어 나누지 않는다 | `fg`(값) → `fg-secondary`(보조) → `fg-tertiary`(메타) 3단. `border-y` 제거, 섹션 경계는 8px 띠만 |
| 4 | **섹션 제목에도 위계.** 전부 같은 굵기 금지 | "대표 메뉴"는 `body-l-semibold` 유지, "사이드"는 캡션 급 라벨로 낮춤(칩 자체가 내용이라 제목이 클 이유 없음) |
| 5 | **여백 리듬을 불균등하게** | 스트립 아래 12 / 상호 블록 아래 20 / 정보 블록 아래 16 / 버튼 줄 아래 16 — 지금의 일괄 `py-3`을 깬다 |
| 6 | **빈 상태는 한 줄 + 인라인 액션.** 일러스트·"아직 ~가 없어요/첫 ~가 되어보세요" 2연타 금지 | 리뷰 빈 상태는 "아직 리뷰가 없어요" 한 줄만(액션은 기여 블록이 이미 갖고 있다). `EmptyState` 재사용하되 `description` 생략 |
| 7 | **숫자는 살리고 나머지는 후퇴** | 가격·확인 횟수·별점만 `semibold` + `tabular-nums`, 단위·날짜·메타는 `fg-tertiary` |

금지는 CLAUDE.md 그대로 유지: 크림+세리프, 카드 색 띠, 이모지 헤더, 그라데이션, 보라, 임의값.

## 변경

### 1. 데이터 — 다중 사진 (`spec.md:137` `photos` 테이블 계획과 일치)

- `lib/types.ts` — `Place`에 `photoUrls: string[]` 추가. `thumbnailUrl`은 **유지**하되 "대표 = `photoUrls[0]`" 주석으로. 마커(`components/map/marker-icons.ts:22`)·카드·`map-view.tsx:277`은 무변경.
- `lib/data.ts` — `RawPlace.thumbnail?: string` → `photos?: string[]`. `dataset()`에서 `photoUrls = (photos ?? []).map(safeAssetPath).filter(nonNull)`, `thumbnailUrl = photoUrls[0] ?? null`. 기존 `safeAssetPath`(`lib/assets.ts`, 규칙 3 가드) 그대로 재사용.
- `lib/mock/places.json` — `"thumbnail": "…"` 2곳(p018:111, p019:162)을 `"photos": [...]`로. p018은 3장, p019는 2장.
- `public/mock/thumb-3.svg`, `thumb-4.svg` 추가 — 기존 2개와 같은 80×80 플레이스홀더 문법(코랄/틸 팔레트, ~280B).

### 2. 사진 스트립 (`components/place-detail/photo-area.tsx` 재작성)

두 상태가 **같은 행 높이**를 쓴다(112px 타일 기준, 요약 실측 후 104~112 사이 조정).

- **사진 있음**: `flex gap-2 overflow-x-auto no-scrollbar -mx-5 px-5`, 타일 `size-28 rounded-12 object-cover`, 마지막에 `[＋]` 타일(`bg-bg-sunken` + `icon-[ci--add-plus]`, `aria-label="사진 추가"`). 기존 `.no-scrollbar` 유틸 재사용.
- **사진 없음**: 같은 크기의 `[＋]` 타일 하나 + 오른쪽 "첫 사진을 올려주세요"(14 medium) / `NaverPhotoLink`. 점선 박스·"아직 사진이 없어요" 카피는 계속 금지.
- **스트립에 `touch-action: pan-x`** — 시트 본문은 `pan-y`가 되므로 가로 스와이프가 시트 드래그를 유발하지 않게 명시해야 한다.

### 3. 닫기 ✕ → 시트 헤더 (`components/ui/bottom-sheet.tsx`, `app/globals.css`)

- detail 모드 헤더에 `onDismiss`를 부르는 ✕ 버튼을 오른쪽 절대 배치(`aria-label="상세 닫기"`, 44px 히트).
- `--sheet-header-h: 26px` → `44px` (detail 모드), `SHEET_DETAIL_HEADER_PX` 상수도 같이. **CSS 변수와 TS 상수는 반드시 같아야 한다**(파일 상단 주석).
- **⚠︎ 리타겟 함정**: 헤더는 `onHeaderPointerDown`에서 즉시 `setPointerCapture`한다. ✕에 `onPointerDown={(e) => e.stopPropagation()}`를 주지 않으면 click이 헤더로 리타겟돼 버튼이 죽는다(2026-09-02 Playwright 확인, `bottom-sheet.tsx` 주석). jsdom은 못 잡으니 **Playwright로 발화 검증**.
- `place-header.tsx`에서 ✕ 제거 → 상호가 전폭을 쓴다.

### 4. 확인 줄 해체

- **삭제**: `components/place-detail/check-line.tsx`.
- **정보 → `place-header.tsx`**: 태그 줄 아래 캡션 한 줄. `<span>어제 확인</span> · <span>확인 4회</span>` 두 조각으로 나눠 둔다 — 기존 테스트의 `getByText("어제 확인")`·`getByText("확인 4회")`가 그대로 통과한다. `relativeCheckLabel`(`lib/time.ts:82`) 재사용.
- **액션 → 새 `components/place-detail/contribution-band.tsx`**: 사이드와 리뷰 사이, 8px 띠로 감싼 블록.
  - "여기 다녀오셨나요?"(16 semibold) / "최근 확인은 3일 전이에요"(12 회색)
  - `[✓ 다녀왔어요]`(outline lg, flex-1) + `[리뷰 남기기]`(outline lg, flex-1)
  - 확인 후: 같은 자리에 `role="status"` 틴트 `[✓ 확인했어요]` — 낙관적 업데이트 + 실패 롤백은 `use-place-detail.ts`의 `checkIn`·`done` 그대로 (UI 완성 기준, 변경 없음).
- **중복 제거**: `review-section.tsx`의 하단 전폭 [리뷰 남기기]와 빈 상태 `action`을 없앤다(기여 블록으로 일원화). 빈 상태는 카피만 남는다.
- `use-place-detail.ts`의 주석 "다녀왔다면" → "다녀왔어요".

### 5. 길찾기 레드 (`components/place-detail/action-row.tsx`)

`variant="ink"` → `variant="brand"` 한 줄. 구성(폭 2/1/1)·크기 유지.

### 6. 수정 입구 통일 — 상태별 점진 노출

`spec.md:67`의 "수정 입구는 필드마다" 원칙은 그대로. 표현만 두 가지로 수렴한다.

- **값 없음 → 눈에 띄는 인라인 입구** (이미 `info-rows.tsx`의 `HoursRow` 빈 상태 패턴)
- **값 있음 → 섹션 헤더 오른쪽 옅은 [수정]** (`Button size="sm"`, 회색)
  - `HoursRow` 값 있을 때 오른쪽 [수정] 추가
  - `MenuList` 헤더 오른쪽 [수정] → 리스트 끝 "가격이 달라졌나요? 수정 제안" 줄 **삭제**(중복)
  - `SidesRow` 헤더 오른쪽 [수정]
  - 사진은 `[＋]` 타일이 곧 입구
- 하단 `FooterLinks`의 "정보 수정 제안"은 안전망으로 유지.
- 전부 `comingSoon` 토스트("준비 중이에요") 연결 — 기존 상수 재사용.

### 7. 시트 스크롤 체이닝

- `app/globals.css` — `.saeu-sheet[data-mode="detail"][data-snap="half"] .saeu-sheet__body`의 `overflow-y: hidden; touch-action: none` 블록 **삭제**. detail 본문은 스냅과 무관하게 `touch-action: pan-y`.
- `components/ui/bottom-sheet.tsx` — non-passive `touchmove` 선점 조건을 확장:
  - `snap === "half"` → 항상 선점(위로 끌면 시트가 full로 올라간다)
  - `snap === "full"` → 기존대로 `scrollTop === 0 && deltaY > 0`일 때만 선점(아래로 끌면 half로)
  - React `onTouchMove`는 passive라 `preventDefault`가 안 먹는 기존 이유는 그대로 유효.
- 이미 있는 "요약으로 돌아오면 `scrollTop = 0`" effect가 그대로 정합성을 지킨다.

### 8. 정보 블록·타이포 위계 (위 규칙 1~7 적용)

- `info-rows.tsx` — `AddressRow`/`HoursRow`를 **하나의 `PlaceInfo` 블록**으로 합친다. 아이콘 삭제, 행 사이 헤어라인 삭제, 도로명(14 `fg`) / 지번(12 `fg-tertiary`) / 영업시간(14 `fg-secondary`)을 한 그룹으로. 우측 액션([복사], [수정])은 각 줄 끝 `sm` 버튼으로 유지. 영업시간 빈 상태만 기존 인라인 입구 문법 유지(규칙 6의 예외 — 값이 없을 때는 눈에 띄어야 한다).
- `sides-row.tsx` — 제목을 `body-l-semibold` → 캡션 급(`caption-l-medium text-fg-tertiary`)으로 낮추고 메뉴 섹션과 같은 카드 안으로. `border-t` 제거(8px 띠가 이미 경계).
- `review-section.tsx` — 빈 상태 `description`("첫 방문자가 되어보세요") 삭제, `action` 삭제(기여 블록이 담당).
- `place-detail-skeleton.tsx` — 확인 줄 자리(`border-y` + pill)를 없애고 새 구조(스트립 자리 없음 → 상호 / 캡션 / 정보 블록 / 버튼 줄)에 맞춘다.
- 여백은 규칙 5의 리듬으로. 새 spacing 토큰은 만들지 않고 기존 유틸 조합만 쓴다(임의값 금지).

### 9. 요약 상태 높이 예산 (390×844, half = 422px)

헤더 44 → 본문 378. 사진 116 + 상호 블록 ~92 + 정보 블록 ~86 + 버튼 줄 64 ≈ 358. 여유 20.
