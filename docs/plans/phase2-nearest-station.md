# 화면 2 정보 블록 — 최근접 지하철역 + 호선 배지

## Context

캐치테이블 상세의 **"⑨ 송파나루역에서 361m"** 줄을 우리 상세에도 넣는다. 서울이 주 커버리지라 "어느 역 근처냐"가 도로명 주소보다 먼저 읽히는 정보다. **역이 멀거나 없으면 그 줄을 안 그리고 주소만** 보여준다.

이미 있는 것으로 대부분 된다 — `lib/geo.ts`의 `haversineKm`·`formatDistance`("130m"/"1.2km", 화면 1 카드가 쓰는 그 함수), `Place.lat/lng`. 없는 건 **역 좌표와 호선**뿐이고, 이번 세션에 OSM에서 실제로 받아 전수 검증까지 마쳤다.

### 실측 (OSM Overpass, 역 노드 473 + 노선 릴레이션 170 + **출구 노드 1,823** × 목 50곳)

| 항목 | 결과 |
| --- | --- |

OSM 릴레이션의 `colour`는 공식 노선색과 일치한다: 1호선 `#004A85` / 2호선 `#00A23F` / 3호선 `#ED6C00` / 4호선 `#009BCE` / 5호선 `#794698` / 6호선 `#7C4932` / 7호선 `#6E7E31` / 8호선 `#D11D70` / 9호선 `#A49D87`.

## 결정

### 1. 표시 — 정보 블록 첫 줄, 호선 배지 + 역명 + **출구 번호** + 거리 (주소는 한 단계 낮춘다)

```
(3)(8) 가락시장역 2-1번출구에서 90m   14 fg          ← 새 줄, 앞에 20px 노선색 원
서울 송파구 올림픽로 300  [복사]        14 fg-secondary ← 도로명 강등
방이동 44-5                          12 fg-tertiary  (그대로)
                    ─ 12 ─
23:00 라스트오더, 월 휴무  [수정]       14 fg-secondary (그대로)
```

- **배지**: `size-5`(20px) 원 `rounded-max`, 노선색 채움 + 흰 숫자 `text-caption-l-semibold`(12/600). 배지끼리 gap 1.5, 마지막 배지↔역명 gap 1.5.
- **환승역은 숫자 호선 전부** 나란히. 목은 최대 2개지만 서울 전체엔 3개(동대문역사문화공원 2·4·5)가 있으므로 개수를 고정하지 않는다.
- **숫자가 없는 노선(수인·분당, 김포 골드라인 등 4/50)은 배지 없이 역명만.** 원 안에 넣을 숫자가 없고 한글 약자("수")는 관습이 아니다. 색 원만 그리면 의미를 못 읽는다.
- **아이콘 없음** — 정보 블록의 "아이콘은 액션에만" 원칙 유지. coolicons에 지하철 아이콘이 아예 없다(`ci` 715개 중 train/subway/metro/rail 0건)는 점도 같은 결론.
- 간격: 역 줄↔도로명 **2**(둘 다 "여기가 어디냐" 묶음), 주소↔영업시간 12, 블록 아래 16 — 기존 문법 그대로. `[복사]`는 **도로명 행 정렬 유지**(역 줄은 flex 행 바깥 독립 `<p>` — 컬럼 안에 넣으면 `items-start`가 복사 버튼을 역 줄 옆에 붙여 "역을 복사"로 읽힌다).
- 거리는 `tabular-nums`.

### 1-b. 한 줄을 못 지키면 출구를 뺀다 (실측 기반 폴백)

320px에서 이 줄이 쓸 수 있는 폭은 **265px**다(Playwright 실측, `px-5` 안쪽). 현재 50곳은 **전부 한 줄에 들어간다** — 최악이 `가산디지털단지역 2번출구에서 140m` + 배지 2개 = **254px**. 즉 지금 데이터에서 잘리는 곳은 0건이고, 아래 규칙은 서울 전역 데이터가 들어올 때를 위한 안전망이다.

넘치는 건 역명이 9~10자인데 배지까지 여럿인 조합이다(`동대문역사문화공원역 11-1번출구에서 990m` + 배지 3 = 326px). 이때 **출구 부분만 떼서** `동대문역사문화공원역에서 990m`(256px)로 줄인다 — 출구 없는 형태는 서울 최장 역명 + 배지 3개에서도 들어간다.

판정은 폭 추정 한 줄로 한다(브라우저 측정 없이 Vitest로 검증 가능):

```ts
/** 14px Pretendard 실측 근사 */
const estWidth = (s: string) =>
  Array.from(s).reduce((w, c) => w + (/[가-힣]/.test(c) ? 12 : /\d/.test(c) ? 8 : 5), 0);
```

`estWidth(라벨) + 26 × 배지수 <= 259`이면 출구를 넣는다.

> **구현 중 정정(2026-09-03)**: 이 근사는 계획서가 적은 것과 반대로 **실측보다 0.8~3.4px 작게** 나온다(브라우저 표본 8개 재측정). 과대추정이 아니므로 안전 방향이 아니고, 265를 그대로 예산으로 쓰면 `총신대입구(이수)역 5번출구에서 320m`(추정 265 / 실측 265.8)가 통과했다가 잘린다. **예산을 265 − 6 = 259로 낮췄다.** 목 50곳은 이 예산에서도 전부 출구를 유지한다(최악 가산디지털단지 255). 뷰포트마다 다르게 판정하지 않고 **320 기준 하나로 통일**한다 — 390에서만 출구가 나타났다 사라지는 편이 더 이상하다.

마지막 안전망으로 줄에 `truncate`를 건다(폴백까지 넘치는 경우는 서울에 없지만, 데이터 오염 시 두 줄로 무너지는 것보다 낫다).

### 2. 색 토큰 9개 신설 + 규칙 예외 명시

`app/globals.css`에 `--color-subway-1` … `--color-subway-9`(위 hex 그대로). 기존 `--color-line*`(경계선)과 이름이 겹치지 않게 `subway-` 접두사를 쓴다. 숫자 호선만 배지를 그리므로 **토큰은 딱 9개로 닫힌다.**

- CLAUDE.md 금지 목록의 **"보라색"과 5호선 `#794698`이 충돌** → decisions.md에 예외를 적는다: 노선색은 우리 팔레트가 아니라 **사실 표기**이고, 20px 배지 안에서만 쓴다. 브랜드 레드 1개 원칙·카드 색 띠 금지는 그대로.
- **접근성**: 9호선 `#A49D87` 위 흰 숫자는 대비가 낮다(≈2.4:1). 배지는 `aria-hidden`으로 두고 줄 앞에 `sr-only`로 "9호선"을 읽힌다 — 색은 보조 신호, 정보는 텍스트가 갖는다.

### 3. 임계값 800m — 넘으면 줄 자체를 안 그린다

출구에서 직선 800m ≈ 실제 도보 1km 남짓, "역에서 걸어간다"의 실질 상한. 목 기준 **47/50**이 걸리고 3곳(까치산 980m·고촌 1,030m·화곡 1,087m)이 주소만 남는다(600m면 45/50 — 바꿀 땐 상수 한 줄).

**임계값은 데이터가 아니라 코드에 둔다.** JSON에는 사실(역·미터·노선)만 굽고 컷은 `lib/data.ts` 상수 → 값을 바꿔도 재생성이 필요 없고 픽스처로 두 분기를 테스트할 수 있다.

### 4. 데이터 — OSM에서 시드 시점에 굽는다 (역 목록은 번들에 안 넣는다)

- 출처 **OpenStreetMap / Overpass**(키 없이 공개, ODbL). 스크립트 헤더와 decisions.md에 출처·라이선스·질의문을 적고, 실서비스 전 공공데이터(국토부 역사 표준데이터, 공공누리 1유형)로 재생성하는 것은 **후속 과제**로 남긴다(소스 어댑터만 교체).
- 역 473개 + 노선 170개 + 출구 1,823개(≈3.6MB 응답)를 클라이언트 번들에 올리지 않는다. 스크립트가 `places.json`에 결과만 굽는다(+≈4KB). 좌표·주소와 똑같은 **시드 시점 외부 파생 사실**이고, Phase 6에선 서버 쓰기 시점에 채우는 컬럼이 될 자리다.
- **출구 매칭**: `railway=subway_entrance | train_station_entrance` 노드를 받아, 최근접 역 노드 **300m 이내**의 출구만 그 역 소속으로 보고 그중 가게에 가장 가까운 것을 고른다.
- **출구 `ref` 정제 필수.** 1,823개 중 대부분은 `ref: "2"` + `description: "월계역 2번출구"`로 깨끗하지만 `"엘리베이터"`·`"한강진역 2번출구"` 같은 오염 값이 섞여 있다 → **`^\d{1,2}(-\d)?$`만 채택**하고 아니면 출구 없는 것으로 취급(역 중심 거리로 폴백).
- 실측으로 확인한 함정 2개:
  - **이름 중복 제거 금지.** 같은 이름 다른 위치가 실재한다(신촌: 2호선↔경의중앙선 **704m**, 수서 360m, 청량리 327m). 노드 473개를 그대로 두고 최근접을 고르면 이름이 저절로 맞는다.
  - **"역" 접미사 이중화.** 이름이 이미 "역"으로 끝나는 건 `서울역` 하나뿐(별도로 `서울`도 있다) → `endswith("역")` 가드. 괄호 이름 `총신대입구(이수)`는 공식 표기라 그대로 둔다.
  - 호선은 `ref`(역번호)에서 뽑지 않는다 — 최근접 50곳 중 32곳에 `ref`가 없다. **노선 릴레이션 멤버십**으로 매칭해야 50/50이 된다. Wikidata의 P81도 못 쓴다(운행 노선이 아니라 "경부선·용산선" 같은 시설 노선, 색도 항목마다 불일치).

## 테스트 · 검증

**Vitest**
- `lib/__tests__/data.test.ts` — 모든 place의 `nearestStation`이 null이거나 `distanceM <= 800`, 목에 null인 곳과 아닌 곳이 **둘 다 존재**(특정 id에 묶지 않아 데이터 재생성에 안 깨진다).
- `components/place-detail/__tests__/station-line.test.ts` — `formatStationLine` 순수 함수: 출구 있으면 `"가락시장역 2-1번출구에서 90m"`, `exit: null`이면 `"고촌역에서 1030m"`, **긴 역명 + 배지 3개면 출구를 뗀다**(`동대문역사문화공원역에서 990m`), `estWidth`가 265 예산 안. **목 50곳 전수**가 배지 수 그대로 한 줄에 들어가는지도 여기서 단언한다(데이터 재생성 회귀 감지).
- `components/place-detail/__tests__/place-detail.test.tsx` — `lines: ["9"]`면 역 줄이 보이고 접근 텍스트에 "9호선", 환승역 `["3","8"]`이면 배지 2개, `lines: ["수인·분당"]`이면 배지 없이 역명만, `nearestStation: null`이면 그 줄이 **없고** 주소만.
