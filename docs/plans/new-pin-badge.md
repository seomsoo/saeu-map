# 신규 핀 표시 — 마커 NEW 배지 + 캡션에서 찾아가기

## Context

**지금 신규 신호는 마커 CSS 한 줄이다** — `.saeu-marker--new { border-style: dashed }`. 36px 원의 2px 카테고리색 링이 실선→점선으로 바뀌는 것뿐이라 실기기에서 거의 안 보인다.

**더 큰 구멍**: 시트 캡션이 이미 **"새로 들어온 집 N곳"**이라고 숫자를 약속하는데(`season-counter.tsx`), **그 N곳으로 가는 길이 없다.** [새로 들어온 집] 칩은 2026-09-05에 빠졌고(`ChipKey`에 없다) 심판대도 관리자로 갔다. 숫자만 남고 경로가 사라진 상태다.

신규는 **주 3곳 예상**(decisions 2026-09-05)이라 마커 배지가 지도를 시끄럽게 만들지 않는다. 반대로 서울 400곳 줌에서는 클러스터에 묻히므로 **배지만으로는 절반**이다 — 이미 그 근처를 보고 있을 때만 도움이 된다. 그래서 두 겹으로 간다.

### 확인한 사실

- **목에 신규가 있다.** 원본 JSON은 `createdAt: 2026-08-27`이 3곳뿐이라 "0곳"으로 보이지만, `lib/data.ts`의 `dataset()`이 `shift = today - MOCK_LATEST_DAY`로 **날짜를 오늘 기준으로 민다**. 실행 중에는 3곳이 7일 이내로 들어온다 — **목 데이터를 손댈 필요가 없다.**
- **`.saeu-marker`는 `overflow: hidden`**이다(썸네일을 원으로 자른다). 배지를 그 안에 두면 잘리므로 **래퍼가 필요하다.**
- **캡션 셋째 조각은 `lg:` 전용**이다 — "모바일 세로·가로 예산에서 캡션이 두 줄이 된다"(design 화면 6 v3). 모바일 퍼스트 제품에서 입구가 데스크탑에만 생기는 문제가 있다(아래 §3).
- **텍스트 스케일에 10px semibold가 없다** — 10px은 `caption-m-regular` 하나뿐이고, 그다음이 `caption-l-semibold`(12px)다.

## 결정

### 1. 마커 위 「NEW」 pill 배지 (사용자 선택)

```
        ┌─────┐
        │ NEW │   ← 브랜드 레드 채움 pill, 흰 글자, shadow-marker
        └──┬──┘
         ╭──┼──╮
         │ 🦐 │   ← 36px 썸네일 원 (그대로)
         ╰─────╯
```

- **DOM**: `isNew`일 때만 래퍼를 씌운다. 400개 마커 전부에 빈 div를 더하지 않는다.
  ```html
  <div class="saeu-marker-wrap">
    <span class="saeu-marker__new">NEW</span>
    <div class="saeu-marker …">…</div>
  </div>
  ```
- **앵커는 그대로** — 래퍼를 정확히 36×36(`position: relative`)로 두고 배지만 `bottom: calc(100% + 4px)`로 넘치게 한다. `size`/`anchor`(36, 18/18)를 안 건드리므로 좌표 매핑이 안 바뀐다.
- **글자 크기는 실측으로 정한다**: 10px `caption-m-regular`(승인 시안)로 먼저 넣고, 흰 글자가 레드 위에서 얇게 뭉개지면 12px `caption-l-semibold`로 올린다. 스케일에 10px semibold가 없어 둘 중 하나다. (실측이 판단을 정하는 방식 — decisions 2026-09-07)
- **`pointer-events: none`** — 배지가 아래 마커의 클릭을 뺏지 않는다. 점선 링(`border-style: dashed`)은 **뺀다**: 배지가 같은 말을 더 크게 하므로 링은 카테고리 색으로 돌려준다(정보 하나를 되찾는다).
- **채운 레드는 규칙 위반이 아니다** — design.md 26줄이 별점 새우를 넣으며 정리한 그대로 "채운 레드 화면당 한 곳"은 **버튼** 규칙이고, 클러스터 레드 원·별점과 같은 결이다.
- **애니메이션 없음.** 깜빡임·펄스는 `design.md:248`의 "신규는 *정보*로 보이고 *참여 요구*로는 보이지 않는다"를 넘는다.
- `getPlaceMarkerIcon`의 캐시 키에 `isNew`가 이미 들어 있다. `innerHTML`에는 리터럴 "NEW"만 — 파일 주석의 규칙(가게 이름 같은 문자열 금지) 그대로다.

### 2. 캡션 「새로 들어온 집 N곳」이 신규 필터를 켠다 (구현 중 두 번 바뀜 — 아래 결과 참조)

- `season-counter.tsx`: N > 0이면 셋째 조각이 **입구 버튼**이 된다(`onShowNew`, 브랜드색). N = 0이면 조각 자체가 없다.
- `use-map-screen.ts`: `showNewPlaces()` — 신규 필터를 **켜고**(멱등) 그 N곳으로 `fitBounds`. 마진은 `fitMargins()` 공용.
- `filter-chips.tsx`: 켜져 있는 동안만 칩 행 **맨 앞**에 `[새로 들어온 집 ✕]`. 상태와 해제는 필터가 사는 자리에 둔다.

### 3. 모바일 캡션 — 실측으로 정한다 (해결: 1번)

셋째 조각이 지금 `lg:` 전용이라 그대로 두면 **입구가 데스크탑에만 생긴다.** 390에서 세 조각이 한 줄에 들어가는지 재고 결정한다.

1. 들어가면 → `lg:` 제한을 풀어 모바일에도 띄운다.
2. 안 들어가면 → **신규가 있을 때만 "이번 주 N곳"과 자리를 바꾼다**(한 줄 예산 유지). "이번 주"는 상시 값이고 신규는 드문 값이라, 드문 쪽이 나타났을 때 자리를 내주는 게 맞다.
3. 문구 축약("새로 3곳")은 2번이 안 될 때만. 카드 라벨 "새로 제보됨"과 어간이 멀어진다.

320·390·430에서 재고 decisions에 기록한다.

### 계획에서 바뀐 것 — §2를 두 번 뒤집었다

**(1) "필터를 켜지 않고 지도만 맞춘다" → 필터를 켠다.** 화면에서 확인하니 아무것도 해결되지 않았다: 목 신규 3곳이 성수·강남·구로로 **16km에 흩어져** fitBounds가 줌 11이 되고 거기서 다시 클러스터로 묶여 **배지 0개**, 목록은 뷰포트 기준이라 그대로 42곳이었다. 필터를 켜면 목록이 3곳으로 좁혀져 **카드가 경로를 준다**.

**(2) 캡션 토글 → 입구/상태 분리**(사용자 지적). 캡션 조각 자체를 토글(눌린 상태 = 틴트)로 만들었더니 **상태 줄에 컨트롤이 섞이고** 켜져 있어도 회색 캡션 안 작은 틴트뿐이라 "왜 3곳이지?"의 답이 안 보였다. 지금은 캡션 = **입구**(멱등한 "켜기"), 칩 행 = **상태·해제**.

**(3) 적용 필터 칩을 맨 앞으로**(실측). 뒤에 붙였더니 칩 행이 가로 스크롤이라 화면 밖으로 나갔다.

**(4) `fitMargins()` 추출** — `submitSearch`·`/gu` 첫 맞춤에 이어 세 번째 호출자가 생겼다(사다리 5).
