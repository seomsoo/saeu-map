# 제보에 기타 메뉴 줄 추가 (spec 4.3 · design 화면 3-3)

## Context

상세는 메뉴 수정에서 **이름을 자유롭게 넣는 줄**을 하나 열 수 있는데(`＋ 메뉴 추가`, `menu-edit-fields.tsx`),
**제보는 구이 1줄 + 회 1줄로 고정**돼 있다 — 스키마부터 `menus: z.array(...).max(2)`로 막혀 있다.
그래서 제보하는 사람은 그 가게의 세 번째 메뉴를 등록 시점에 남길 방법이 없고, 등록한 뒤 상세로 들어가 다시 넣어야 한다.

사용자 요청(2026-09-09): **제보에서도 기타 메뉴를 추가할 수 있게 한다.**

## 결정

1. **최대 5줄**(사용자 선택) — 구이 1(필수) + 회 1(선택) + **기타 3**. 기타 상한은 **회 토글과 무관한 고정값**이다:
   남는 자리로 계산하면 기타를 4줄 채운 뒤 "새우회도 팔아요"를 켜는 순간 6줄이 되고, 스키마에 걸려
   **사용자가 이유 모를 등록 실패**를 본다(푸시 전 점검에서 발견, 2026-09-09). 크롤 가게의 메뉴가 중앙값 3줄·최대 5줄이라
   그 분포와 맞고(`menu-edit-fields.tsx` 주석), 제보 화면이 길어지지도 않는다.
2. **기타 줄에 카테고리(구이·회·기타) 선택을 두지 않는다**(권고, 사용자 확인). `Place.menus`에는 **줄별 카테고리를
   저장하는 자리가 없고**(`Menu` = raw·name·price·unit·unit_raw), 회 여부는 이미 "새우회도 팔아요" 토글이
   담당한다 — 그게 `tags`에 `raw`를 붙이는 유일한 신호다. **저장될 곳이 없는 선택지는 만들지 않는다.**
   상세의 추가 줄과 같은 문법(이름·가격·단위만)이 곧 "기타"다.
3. **UI는 `step-menu.tsx`에만 넣는다.** `MenuFields`는 상세의 메뉴 제안 시트와 **공유**하므로(decisions 2026-09-08
   "같은 값을 두 곳에서 다르게 받지 않는다") 거기 손대면 시트까지 바뀐다. 기타 줄은 제보 3단계의 것이므로
   `MenuLine`(이미 export돼 있다)만 가져다 쓴다.

## 변경

- `lib/data.ts` — `REPORT_MENU_MAX = 5` 상수 + `reportInputSchema.menus`를 `max(2)` → `max(REPORT_MENU_MAX)`
- `components/report/use-report-flow.ts` — `ReportDraft.extras: MenuDraft[]`, `menusOf`가 검증된 기타 줄을 뒤에 붙인다,
  `addExtra` · `removeExtra` · `patchExtra`
- `components/report/step-menu.tsx` — 회 줄 아래 기타 줄 목록(줄마다 [삭제]) + `＋ 메뉴 추가`(상한에서 사라진다),
  [다음]에서 줄마다 검증
- 테스트 — 기타 줄을 넣고 등록하면 `Place.menus`에 그대로 들어오는지, 상한에서 추가 버튼이 사라지는지,
  빈 기타 줄은 [다음]을 막는지
