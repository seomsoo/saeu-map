# /admin — 운영 화면 (spec 4.4·4.5 · design 화면 10 신설)

## Context

`feat/pending-flows` 위에 쌓은 브랜치(`feat/admin`). PR은 함께 올린다.

앞 브랜치가 사용자 화면의 막힌 입구를 전부 열었다. **그것들이 만들어내는 일감이 도착할 곳이 아직 없다** — `/admin`은 라우트조차 없고(spec 4.5), roadmap Phase 5.5의 남은 항목이다.

### 조사에서 나온 것 (플랜을 바꾼 사실들)

1. **신고·요청이 아무 데도 저장되지 않는다.** `flagPlace`·`reportPlace`·`reportPhoto`·`submitOwnerRequest`는 zod 검증 + 400ms 지연만 하고 **버린다**. admin에 보여줄 행이 없으므로 **저장소부터 만들어야 한다**. (`getPlaceEdits()`는 앞 브랜치에서 이미 만들었다 — 수정 이력 탭은 데이터가 있다.)
2. **Place에 운영 상태 필드가 없다.** spec 4.4의 "검증 전 / 확인됨"과 spec 5의 "신고 3회 → 자동 숨김(삭제 아님, 복구 가능)"을 담을 자리가 `Place`에 없다.
3. **`Session`에 관리자 표시가 없다.** spec 4.5 "카카오 로그인 + `profiles.is_admin`, 비관리자는 404 위장".
4. **design.md에 관리자 화면 블록이 없다.** 화면 1~9는 전부 사용자 화면이다 → **화면 10을 새로 쓴다**(roadmap 규칙: 화면이 있는 작업은 design 블록 먼저).
5. **spec에 잔재가 있다.** 4.4의 "탭이 곧 제출 → 수정 제안 큐", 4.5의 "수정 제안 큐" — 앞 브랜치에서 즉시 반영으로 뒤집혀 큐가 없어졌다.
6. **사후 확인은 폰에서 해야 한다.** spec 5가 "제보 시 텔레그램 알림 → 운영자 24시간 내 사후 확인(**플레이스 링크 30초 체크**)"이라고 정의한 행동은 알림을 받은 자리에서 하는 것이다. spec 4.5의 "데스크탑 표"를 그대로 읽으면 폰에서 못 쓰는 화면이 된다.

## 결정 (사용자 선택 2 + 권고 6)

1. **통계 탭을 하나 더 둔다**(사용자 선택) — spec 4.5의 탭 4 → **5**. 참여 추이(제보·확인·리뷰·수정 일별)·익명/카카오 비율·상위 가게. 목 데이터라 숫자는 가짜지만 레이아웃과 집계 함수는 Phase 6에서 그대로 산다.
2. **방문자 분석은 Cloudflare Web Analytics**(사용자 확인) — 스크립트 한 줄·무료·쿠키리스(동의 배너 불필요), 이미 CF Workers에 배포 중이라 설정이 가장 짧다. **GA4는 채택하지 않는다**: ~50KB가 LCP 예산(error 12s, decisions 2026-09-07)을 먹고 쿠키 때문에 첫 화면에 동의 배너가 뜬다 — 지도를 가리는 배너는 최악이다. 붙이는 건 런칭 전이고 이번엔 spec 6에 기록만. **네이버 서치어드바이저는 분석 도구가 아니다**(검색 색인·노출 관리) — spec 6에 이미 있고 목적이 다르다.
3. **(권고) 탭 2를 "신고·요청"으로 넓힌다.** spec 4.5는 "신고·숨김(복구·폐업 처리)"인데, 정보 수정 제안(사유 시트)·사장님 요청도 갈 곳이 없다. 셋 다 **사용자가 알려온 일감**이고 처리 흐름이 같다(열림 → 처리함/무시함). 한 탭에서 종류 칩으로 거른다.
4. **(권고) 사후 확인 탭만 모바일에서 쓸 수 있게 만든다**(위 6번). 나머지 탭은 데스크탑 표 그대로 — 폰에서 열면 가로 스크롤이다. 사후 확인은 카드 한 장 = 제보 하나로 떨어지게 해서 폰에서 [확인] 한 번에 끝난다.
5. **(권고) 저장소는 `reports` 하나로 합친다.** 가게 신고·사진 신고·정보 수정 제안·사장님 요청이 `kind`만 다른 같은 모양이다(spec 6 스키마도 `reports(수정 제안·신고·폐업)` 한 테이블이다).
6. **(권고) 관리자 판정은 목 토글.** `Session.isAdmin`을 두고 `/test`처럼 dev 전용 스위치로 켠다(`?admin=1`은 쓰지 않는다 — 프로덕션에서 URL로 켜지면 안 된다). 실제 판정은 Phase 6 `profiles.is_admin` + 서버 검증.
7. **(권고) 비관리자는 `notFound()`** — 로그인 유도도, "권한 없음"도 아니다(spec 4.5 "404 위장"). 관리자 화면의 존재 자체를 알리지 않는다.
8. **(권고) 되돌리기는 확인 없이 즉시 + 토스트.** `PlaceEdit.before`를 그대로 쓰면 되고, 되돌린 것도 이력에 남아 다시 되돌릴 수 있다(대칭). 파괴적이지 않은 동작에 확인 모달을 두지 않는다 — 파괴적인 **가게 삭제**만 확인 모달(탈퇴 확인과 같은 문법).

## 디자인 언어 — 화면 10 (전문은 design.md에 쓴다)

사용자 화면(1~9)은 **지도 위 시트/패널**이 그릇이지만 관리자는 **표**다. 다른 그릇이므로 새 규칙이 필요하지만, **토큰·공용 컴포넌트는 그대로 쓴다** — 새 팔레트·새 버튼을 만들지 않는다.

- **그릇**: 지도 없음. 흰 배경 + 최대 폭 1200 가운데, 좌우 여백 24. 상단 44 헤더(왼쪽 "새우맵 관리", 오른쪽 현재 계정·[사용자 화면으로]).
- **탭**: `Segmented` 5칸(사후 확인 · 신고·요청 · 수정 이력 · 검색 · 통계) — 내 활동 탭과 같은 컴포넌트다. 각 탭 라벨 오른쪽에 **미처리 수 배지**(있을 때만).
- **표**: 헤더 행(12 fg-tertiary, 헤어라인 아래) + 데이터 행(14, 행 높이 52, 행 사이 헤어라인, hover에 `bg-bg-sunken`). 셀 정렬은 텍스트 왼쪽 / 숫자·날짜 오른쪽 tabular. **띠·줄무늬·카드 그림자를 쓰지 않는다** — 표는 밀도가 값이라 장식이 읽기를 방해한다.
- **행 액션**: 오른쪽 끝 고정 열. 주 액션만 채운 버튼(sm), 나머지는 아웃라인·텍스트. **한 행에 채운 버튼은 하나**(화면당 하나 규칙의 표 판).
- **상태**: 4상태 공용 컴포넌트 그대로(`Skeleton` 행 5개 / `EmptyState` / `ErrorState` + [다시 시도]).
- **사후 확인만 모바일 대응**: `lg` 미만에서 표 대신 **카드 목록**(상호 20 semibold / 구·대표 메뉴·가격 / 등록 N일 전 / [플레이스 열기] [확인]). 같은 데이터, 같은 훅, CSS로 자리만 바꾼다(화면 6~9와 같은 규칙).

## 구현 전에 정한 것 (사용자 확인, 전부 권고안)

9. **[확인]은 `verifiedAt` 배지만 찍는다.** 카드·마커의 "새로 제보됨"은 건드리지 않는다 — 그건 7일 타이머(`isNew`)이고 "새로 생겼다"는 *정보*지 "검증했다"는 뜻이 아니다. 둘을 묶으면 진짜 새 가게인데도 사용자가 신규를 알 길이 없어진다.
10. **신고 3회는 사람 기준 중복을 제거하고 센다.** 같은 익명 id의 반복은 1 — 혼자 세 번 눌러 남의 가게를 내리는 걸 막는다(spec 5 "악성 신고자 섀도 밴"과 같은 결).
11. **삭제는 소프트다** — `hiddenAt` + `removedByOwner`. spec 5가 "재제보 시 관리자에게 경고 표시"를 요구하므로 기록이 남아야 한다. 복구도 된다.

**security-reviewer**: 높음 1·중간 4·낮음 5 반영.
- **높음 — 자동 숨김이 무기였다.** 익명 id는 로그아웃·새로고침마다 새로 나오고 **회전 비용이 0**이라 한 사람이 세 번 눌러 남의 가게를 지도에서 지울 수 있었다. "사람 기준으로 센다"는 내 주석이 거짓이었다. **철회하고** 관리자 표시로만 낮췄다 — 자동 숨김은 spec 5 스팸 4겹(Turnstile·속도 제한·기기 식별)이 선 뒤에 켠다.
- **중간 — 숨김이 KST 자정에 풀렸다.** `dataset()`이 날짜마다 원본에서 다시 만드는데 숨김을 캐시 안 객체에만 찍었다 → `placeOps` 맵으로 캐시 밖에(`deletedReviewIds`와 같은 규칙).
- 중간 — 신고 탭이 사용자 읽기로 조인해 숨긴 가게의 상호·[복구]가 사라졌다(오탐을 되돌릴 길이 없었다) → `getPlacesForAdmin`.
- 중간 — 탈퇴 시 `actor`만 떼고 **사장님 연락처·내용이 남았다**(정작 개인정보는 그쪽이다).
- 중간 — `getMyReviews`가 숨긴 가게를 안 걸렀다(상호가 보이고 누르면 404).
- 낮음 — 시즌 카운터·쓰기 4종의 숨김 누락, 신고의 `placeId` 미검증, `revertPlaceEdit`의 actor 순서, **GA4가 `/admin`에서도 로드**.

**gap-sweeper**: 미구현 5·부분 7 중 코드로 고칠 수 있는 것 전부 반영.
- 표 **헤더 고정이 안 먹고 있었다** — `overflow-x-auto`를 주면 overflow-y도 auto가 되어 sticky가 그 상자에 갇힌다. lg부터 가로 스크롤 상자를 걷었다.
- 로딩에 표 헤더가 없어 탭 전환 때 화면이 뛰었다.
- 빠진 액션: [가게 열기](신고·요청·검색), [사진 내리기](`deletePlacePhoto`).
- **배지가 [확인] 뒤에도 그대로였다** — 액션 후 숙제 수를 다시 센다.
- 관리자 손삭제에 `byOwner`가 붙어 재제보 경고가 엉뚱하게 떴다.
- **문서끼리 어긋난 것**: spec 4.4의 "확인됨"·"[수정 이력으로]"는 승인 큐 시절 잔재라 정정.

**검증**: `pnpm typecheck && lint && test`(497) · Playwright 1440×900·390×702 · workerd 스모크(`/` `/place` `/gu` 200, `/place/nope` **404**, `/admin` 비관리자에게 관리자 흔적 0·제목 중립, GA4 ID 없으면 스크립트 0건).

### 남은 것 (Phase 6)

- **`/admin`은 HTTP 200이다.** 목 세션이 클라이언트에만 있어 서버가 관리자인지 알 수 없다 — 내용만 404이고 상태 코드는 200이다. 서버가 `profiles.is_admin`을 읽으면 그때 진짜 404가 된다.
- **서버 검증·RLS가 없다.** `requireAdmin()`은 목 게이트다(spec 4.5 "프론트 체크는 장식").
- **자동 숨김**은 스팸 4겹이 선 뒤에.
- 사장님 요청 연락처의 **보관 기간** — 처리 후 만료시키는 자리는 아직 없다.
