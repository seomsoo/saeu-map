> 2026-08-28. 핸드오프 브리프 v1 + 기획 세션 결정 병합본.

## 1. 정체성

- **무엇**: 서울 새우구이 지도. 크롤 시드 452곳(서울 421)으로 열고 유저 제보·확인으로 갱신.
- **구조는 "지금 되는 집", 카피는 담백하게.** 갱신 루프(모든 활동 → 확인일 갱신)가 제품의 핵심이지만, 화면에서는 "○일 전 확인"으로만 표현한다. "지금"을 크게 외치지 않는다.
- **태그라인**: 화면에는 없음. OG·검색 결과용 한 줄만. 후보: "그 집, 새우 돼요?" / "서울 새우구이 421곳" — 런칭 직전 스레드 글과 함께 확정.
- **레퍼런스**: 야장맵·거지맵·고수맵(구조), 캐치테이블·테이블링(UI 무드).

## 2. 데이터 — 수집 완료

수집 파이프라인·결과·로컬 자산은 v1 브리프 2장 그대로 유효.

- 서울 25개 구: 주력 259 / 취급 165 / 생새우회 36. 태그 기준 새우구이 397 / 생새우회 232, 42%가 둘 다.
- 수집 필드: 상호, 좌표, 도로명+지번, place_id, 카테고리(내부), 새우 메뉴명+가격, 네이버 플레이스 링크.
- 네이버 오픈API는 NAVER API HUB(NCP) 이관됨. 지역검색 엔드포인트·헤더는 v1 참조.
- **남은 검수**: excluded.csv 및 구이 메뉴 없는 37곳(생새우회만 28 + 오탐) 눈으로 확인.

### 가공 규칙 (크롤 → 서비스)
- 네이버 원본 카테고리·새우 무관 메뉴 버림.
- **카테고리 = 다중 태그**: `새우구이` / `생새우회`. 하나로 강제하지 않음. 필터 다중 매칭.
- **새우 전문 플래그**: 내부 분류 "주력" 259곳 → true. 제보 핀은 기본 false, 운영자가 켠다.
- 사이드 3종: `머리버터구이` / `라면` / `볶음밥` — 있으면 강조, 없으면 회색.
- **좌표 → 최근접역·출구·호선 파생**(OpenStreetMap/Overpass, ODbL): 시드 시점에 구워 넣는다(`scripts/add_nearest_station.py`). 좌표·주소와 같은 성격의 외부 파생 사실이라 런타임에 계산하지 않고, Phase 6에선 서버 쓰기 시점에 채우는 컬럼이 된다. 실서비스 전 공공데이터로 재생성은 후속 과제.
- 가격 단위 분리: 1kg / 500g / 한판 / 반판 / N마리 / 大中小 등. 메뉴명에서 파싱, 유저 보정.
- 메뉴명 정제(이모지·프로모션·옵션 제거), raw 원문은 DB 보존 + 표시용 필드 분리.

## 3. 법적·운영 원칙

v1 브리프 4장(수집 OK 범위, 리뷰·사진 재배포 금지, 판례 근거) 그대로 + 운영 원칙 추가:

- **사장님 삭제 요청은 1회로 즉시 처리**(24시간 내). 다투지 않는다.
- 상세 하단에 "사장님이신가요? 정보 수정·삭제 요청" 연락 창구 상시 노출.
- 리뷰 신고 접수·조치 시각을 기록으로 남긴다(분쟁 대비).
- 규모가 커지면 크롤 리스크 재검토.

## 4. 화면

### 4.1 지도 메인 — 풀스크린 지도 + 바텀시트 (모바일 퍼스트)
- 상단: 지도 위엔 **검색 블록 + 칩 행 두 층만**(검색바는 우리 데이터 내 가게명·동네). 제보·현위치는 시트 가장자리 위 FAB, 이벤트는 시트 안 행 (2026-09-02).
- **카테고리**: 드롭다운 칩 [전체 ▾] — 전체 / 새우구이 / 생새우회 (다중 태그 매칭. 데이터 태그는 grill/raw).
- **칩**: 사이드 3종(머리버터구이·라면·볶음밥) · "새로 들어온 집" · "찜한 곳" — 최대 5개(상한 도달, 2026-09-02). 켜진 칩은 AND.
- **정렬**: 가까운순(기본) / 최근 확인순 / 확인 많은 순. 랭킹·TOP10 없음.
- **시즌 카운터**: 시트 헤더 캡션 한 줄 "오늘 N건 확인됐어요 │ 이번 주 N곳" (라이브 점, 최다 확인 없음 — 2026-09-02).
- **이벤트 카드 슬롯** 1개(제목·링크·기간을 설정값으로, 닫기 가능): 까주기 테스트 → 축제 일정 → 등 갈아끼움.
- **마커**: 개별 핀 = 썸네일 원 + 카테고리색 링(구이=코랄, 회=틸, 둘 다=구이색 우선; 사진 없으면 색점 플레이스홀더), 클러스터 = 레드 원 + 가게 수. 신규 점선 링, 6개월 무활동 시 투명도만 낮춤. 커스텀 새우 에셋 완성 전까지 색점.
- 리스트 카드: 썸네일 / 상호 / 거리·구·카테고리 / 사이드 미니칩 / "○일 전 확인". 대표메뉴·가격은 상세로(2026-09-02). 거리는 내 위치, 없으면 지도 중심 기준.

### 4.2 상세 — 바텀시트 확장 (탭=요약, 드래그=전체, 스와이프=닫기)
확정 순서(위→아래) — 2026-09-03 리디자인으로 10항목 → 9항목:
1. **사진** — 가로 스크롤 스트립(176×128, 여러 장, **한 가게 10장까지**). 끝은 항상 `＋` 타일이라 사진이 있어도 옆에 계속 추가한다(10장이 차면 안내 타일). **탭하면 전체 화면 뷰어** — 좌우 스와이프로 넘기고 아래에 업로드 날짜와 [신고]가 붙는다(익명 업로드라 사진 신고만은 준비 중 토스트로 미루지 않는다). 빈 상태는 전폭 블록 하나(＋ / "아직 사진이 없어요" / "첫 새우를 올려주세요", 블록 전체가 올리기 표적). "네이버에서 사진 보기" 링크는 사진 유무와 무관하게 리뷰 끝에 둔다.
2. **상호 블록** — 상호 / 카테고리 · 구(상세 안에서는 색점 없이 텍스트) / **"○일 전 확인 · 확인 N회"** 캡션. 신선도는 여기서 조용히 말하고, 확인 **액션**은 7번이 갖는다.
3. **정보 블록** — **최근접 지하철역**(호선 배지 + "가락시장역 2-1번출구에서 90m"), 주소(도로명+지번, 복사 버튼), 영업시간을 헤어라인 없는 한 덩어리로. 위치·영업시간 그룹마다 앞에 아이콘 열(핀·시계)이 선다. **주소는 기본이 접혀 있고 역 줄을 누르면 펼쳐진다** — 역 줄이 그 드롭다운의 헤더다(주소는 길찾기·복사할 때만 필요한 값이라 상시 두 줄을 먹지 않는다, 2026-09-03). 역이 800m 밖이면 헤더가 없으니 드롭다운도 없고 주소가 그냥 보인다. 지번은 시·구 접두어를 떼고 동·번지만 쓴다("가락동 600"). 역 줄이 첫 줄이고 도로명은 한 단계 낮다 — 서울에서는 "어느 역 근처냐"가 도로명보다 먼저 읽힌다(캐치테이블 문법). 거리는 역 중심이 아니라 **가장 가까운 출구까지의 직선거리**를 10m 반올림하고, **역이 800m 밖이면 줄 자체가 없다**(경기·외곽은 주소만). 숫자 없는 노선(수인·분당 등)은 배지 없이 역명만(2026-09-03). 영업시간은 제보 메모 문자열 그대로("23:00 라스트오더, 월 휴무"), "영업 중" 판정은 없음(구조화 데이터가 없다, 2026-09-02). 빈 상태면 "영업시간을 알려주세요"가 입력 입구.
4. 버튼 3개: **길찾기(네이버 딥링크, 주 버튼 — 이 화면의 유일한 채운 레드)** / 공유 / 찜(하트 토글)
5. 대표 메뉴 — 단위 + 가격(tabular). 수정 입구는 섹션 오른쪽 [수정] 하나.
6. 사이드 3종 칩 (있음 = 아웃라인 + 체크 / 없음 = 회색)
7. **기여 블록** — "여기 다녀오셨나요?" + **[✓ 다녀왔어요]**(원탭 확인 +1, 취소 없음, 핀당 일 1) [리뷰 남기기]. 정보 행 안에 인라인으로 있던 확인 줄(구 3번)을 해체해 액션만 모은 자리다(2026-09-03).
8. 리뷰 — 별점+후기+사진. **리뷰 3개 미만이면 평균 별점 숨김**, "확인 N회"만. 빈 상태는 한 줄뿐(액션은 7번이 갖는다).
9. 하단 작게: 정보 수정 제안 · 신고 · **사장님이신가요?**

**수정 입구는 필드마다**(사진·영업시간·메뉴·사이드·리뷰·하단). "수정" 버튼 하나에 몰지 않는다. 표현은 두 문법으로만: 값이 없으면 그 필드 자리가 인라인 입구, 값이 있으면 섹션 오른쪽에 옅은 [수정](2026-09-03). 수정 제안은 즉시 반영이 아니라 승인 큐 경유. 예외: 사진(즉시), 다녀왔어요(즉시).

신규 핀(7일 이내)은 상단에 배너: "새로 제보된 곳이에요 · 아직 검증 전이에요 · 다녀오셨다면 확인해주세요".

### 4.3 제보 플로우 — 바텀시트 안 4단계
1. **가게명 검색** (우리 DB 자동완성) → 매치 있으면 "이미 있어요" → 기존 상세로 전환(다녀왔어요/수정/사진). 없으면 "새로 등록".
2. **위치** — 현 위치 중심 지도에서 탭·드래그로 핀 확정 + 주소 검색(도로명) 보조. 확정 시 상호 유사도+좌표 150m 중복 재검사(`same_place` 재사용) + 핀 자리 30m 근접 검사(상호 무관); 기존 마커를 탭해도 그 가게로 묻는다. 의심 매치 시 [이 가게예요/다른 가게예요], "다른 가게예요"면 등록되되 관리자 큐에 중복 의심 표시(`duplicateSuspectOf`). 주소 검색 결과는 저장하지 않는다(규칙 2) — 저장은 사용자가 확정한 핀 좌표와 그 좌표로 판정한 시군구(전국, 서울 밖은 "김포시(경기)" 표기)뿐이고 도로명·지번은 비워 둔다(decisions 2026-09-04).
3. **메뉴·가격** — 메뉴명·가격·단위 칩 한 줄(필수). "새우회도 팔아요" 토글 → 회 줄. 카테고리는 메뉴 줄에서 자동.
4. **선택 항목 한 화면** — 사진 / 사이드 3체크 / 영업시간 메모. CTA는 하나 — 아무것도 안 넣었으면 "건너뛰고 등록", 하나라도 넣었으면 "등록하기"(decisions 2026-09-04).
- 완료: 즉시 노출 안내 + 공유 카드 + 리뷰 유도. 필수는 가게명·위치·메뉴 한 줄 셋뿐.
- 엣지: 프랜차이즈(150m 밖이면 별개 핀), 이전 가게(새 핀은 제보로 — 기존 핀 이전 처리·리다이렉트는 Phase 6 관리자 큐, decisions 2026-09-04).

### 4.4 신규 패널 ("심판대" 역할, 이름 미정 — 후보: 수족관 / 갓 들어온 집)
- 지도 위 "신규 N곳" 버튼 → 바텀시트 리스트: 등록일·구·대표메뉴·가격·"검증 전".
- 리스트에서 바로 [맞아요(확인 +1)] / [정보가 달라요].
- 확인 1회↑ → "확인됨", 7일 경과 → 패널에서 제외. 빈 상태: "제보하면 여기 떠요".

### 4.5 관리자 /admin
- 카카오 로그인 + profiles.is_admin. 비관리자는 404 위장.
- 탭 4: 사후 확인(새 제보) / 신고·숨김(복구·폐업 처리) / 수정 제안 큐 / 검색(직접 수정·삭제).
- 서버 측 is_admin 검증 + RLS. 프론트 체크는 장식.

### 4.6 SEO·공유
- /place/[id] 가게별 SSR 페이지(얕은 라우트·공유 딥링크는 Phase 2에서 선행, SSR 메타·OG·진짜 404는 Phase 5 — 2026-09-02), /gu/[name] 구별 25페이지, sitemap, 네이버 서치어드바이저 등록.
- OG 이미지 동적 생성(next/og): 핀 공유 카드, 테스트 결과 카드, 구별 카드.
- 공유 링크 → 해당 핀 열리는 딥링크.

## 5. 규칙

### 노출
- **모든 제보 즉시 노출** (사진 유무 무관). 신규 7일 라벨 + 신규 패널 수록.
- 제보 시 텔레그램 알림 → 운영자 24시간 내 사후 확인(플레이스 링크 30초 체크).
- 신고 3회 → 자동 숨김(삭제 아님, 관리자에게 보임·복구 가능). 악성 신고자 섀도 밴.
- 사장님 요청 1회 삭제. `removed_by_owner` 기록, 재제보 시 관리자에게 경고 표시.

### 리뷰
- 별점(필수) + 후기(선택) + 사진(선택) 한 폼. 3개 미만 평균 숨김. 리뷰 등록 시 확인일도 갱신.
- **로그인(카카오) 필수.** 비로그인이 "리뷰 남기기" 누르면 로그인 시트 → 완료 후 쓰던 리뷰 화면으로 복귀. 익명 별점 없음(조작 방어가 우선, 익명 참여는 다녀왔어요이 담당).
- 닉네임은 카카오 프로필 기본, 수정 가능.
- **본인 수정·삭제 가능** (내 활동 > 내 리뷰, 상세의 내 리뷰). 수정 시 "수정됨" 표시만. 삭제는 소프트(deleted_at) — 화면·평균에선 즉시 제외, 관리자에겐 보임(악성 반복·분쟁 기록용). 리뷰를 지워도 checkins 확인 기록은 유지.
- 광고성 리뷰는 신고 기반 심사. 랭킹 없음(조작 표적 제거). 다녀왔어요 취소 기능은 없음.

### 로그인
- **익명 유저 자동 생성(Supabase anonymous auth)이 기본.** 모든 활동이 익명 ID로 기록.
- 카카오 로그인은 선택(linkIdentity로 기록 승계). 조회·제보에 로그인 강제 없음.
- **경계**: 익명 가능 = 다녀왔어요·제보·사진·수정 제안·신고·찜(기기 한정) / 로그인 필요 = 리뷰(별점+후기).
- 로그인 시: 기록·찜 기기 간 유지, 닉네임 고정, 내 활동 페이지, (후일) 알림.
- **찜**: bookmarks(user_id, place_id). 확인일 갱신 안 함("가고 싶다"지 "가봤다"가 아님). 지도 칩 "찜한 곳" + 내 활동 찜 탭(기본). 익명 찜 3개째에 "로그인하면 안 날아가요" 넛지 1회 — 벽은 아님.
- **내 활동 페이지**: 찜 / 내 리뷰 / 내 제보 탭. 맨 아래 로그아웃·**탈퇴**(탈퇴 시 리뷰 등 개인 데이터 완전 삭제).
- 공급자는 카카오만. 30일 무활동 익명 유저 월 1회 정리 크론(활동 기록 있는 유저 제외).

### 스팸 4겹
1. Turnstile(모든 쓰기) + Cloudflare WAF·봇 차단
2. 속도 제한(Upstash: 제보 시간당 5, 다녀왔어요 핀당 일 1, 신고 일 10 — 사진 신고는 상세 사진 뷰어 하단, 가게 신고는 상세 맨 아래 줄) + 급증 텔레그램 알림
3. 내용: 중복 감지, URL 패턴 거부, 욕설 블록리스트, 이미지 sharp 재인코딩+EXIF 제거, presigned 5분
4. RLS(자기 행만 쓰기) + zod 검증 + 섀도 밴 + 관리자 차단 목록

## 6. 기술

### 스택
- Next.js(App Router, TS) + Tailwind / **네이버 지도 SDK(NCP 신규 Maps 상품)** — Web Dynamic Map 월 600만 건 무료·초과 0.1원/건, 지오코딩도 Maps(월 300만 무료)로 통일, 콘솔에서 사용량 알림(월 400만) 설정 / Supabase(익명 auth·RLS·Postgres) / Cloudflare Workers(OpenNext 어댑터 — decisions.md 2026-09-01, 원안 Vercel에서 변경)
- 사진: NCP Object Storage(크레딧, ~11/30) → 이후 Cloudflare R2 이전. 업로드 시 1200px webp 리사이즈.
- 길찾기·플레이스 링크도 네이버(딥링크·링크). 카톡 공유·카카오 로그인은 유지(지도 SDK와 무관). VWorld 지오코딩은 네이버 Geocoding으로 대체.
- 운영: Sentry, 텔레그램 봇, Cloudflare(DNS·Turnstile), Upstash, 네이버 서치어드바이저.
- 도메인: 새우맵.kr(공유·구두용) + saeumap.kr(정식·OG·이메일) — 등록 필요.
- 비용: 무료 티어 시작. 핀 목록 Next.js 캐시(revalidate) 필수 — 이거 하나로 MAU 1만→5만. Supabase 잠들지 않게 일일 크론 핑. Pro 전환 신호: egress 4GB, 트래픽 급증, 백업 필요.

### 스키마 원칙 (확정은 UI 이후)
- **확인일은 컬럼이 아니라 `checkins` 이벤트 테이블에서 계산.** (누가·어느 가게·언제·무슨 활동) 한 줄씩 append. 타임라인·최근확인순·확인수·스탬프가 쿼리로 나옴.
- reviews 별도 테이블(별점·후기·사진), 등록 시 checkins에도 한 줄.
- places(raw 보존+표시 필드), place_categories(다대다), menus, photos, reports(수정 제안·신고·폐업), profiles(is_admin).
